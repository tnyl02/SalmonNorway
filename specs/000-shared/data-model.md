# ข้อมูลที่หลายฟีเจอร์ใช้ร่วมกัน (shared data model)
Status: v10 | Updated: 2569-11-11 (DM-07 เพิ่ม action notify ตามคำขอของ 003 ต่อจาก v9 ของ 002: ค่าสถานะ snake_case, คอลัมน์ของ 003 และค่าวัตถุประสงค์การยืม 3 ค่าใน DM-06) | Source: plan.md ข้อ 4 ของ 001, Infrastructure บน Miro

เขียนเฉพาะสิ่งที่มากกว่า 1 ฟีเจอร์ใช้ ฟิลด์ที่ใช้เฉพาะฟีเจอร์เดียว ไปอยู่ใน plan.md ของฟีเจอร์นั้น
ชื่อตารางในวงเล็บคือชื่อใน PostgreSQL (CON-TECH-01)

- DM-01 Department ภาควิชา (`department`): รหัส ชื่อ
- DM-02 Category ประเภทอุปกรณ์ (`category`): รหัส ชื่อ (ตายตัวหรือเพิ่มได้ รอ Q-04 ของ 001)
- DM-03 EquipmentModel รุ่น/ชนิด (`equipment_model`): ชื่อรุ่น ประเภท ภาควิชาเจ้าของ
- DM-04 EquipmentItem อุปกรณ์รายชิ้น (`equipment_item`): รหัสครุภัณฑ์ไม่ซ้ำ (CON-DATA-03), รุ่น,
  สถานะ 1 ใน 3 ค่า (CON-DATA-01), เวลาที่สถานะเปลี่ยนล่าสุด
- DM-05 Loan การยืม (`loan`): อุปกรณ์รายชิ้น ผู้ยืม ประเภทการยืม (ปกติ / ค้างคืน)
  กำหนดคืน (**วันที่และเวลา** ยืมปกติ = 16:00 วันเดียวกัน ตาม DOM-LOAN-01,
  ค้างคืน = 16:00 ของวันที่สิ้นสุดการยืมที่ผู้ขอระบุ ปิด Q-SH-04 2569-11-11) เวลาคืน (ว่าง = ยังไม่คืน)
  สร้างโดย UC-08 ปิดโดย UC-09
  ฟิลด์ตอนรับคืน (เพิ่มโดย 006 ใน `0010_return.up.sql` ว่างได้ทั้งหมด ไม่กระทบ 001, 005): สภาพตอนรับคืน (`return_condition` ปกติ / ชำรุด FR-RET-02),
  คืนเกินกำหนด (`returned_late` FR-RET-06) คืนแล้วต้องมีครบทั้งเวลาคืน สภาพ และคืนเกินกำหนด
- DM-06 BorrowRequest คำขอยืม (`borrow_request`): ประเภท (ปกติ / ค้างคืน), สถานะของคำขอ,
  วัตถุประสงค์ (RQ-18) 3 ค่าที่ 002 กำหนด 2569-11-11: เพื่อการเรียน / เพื่อทำกิจกรรม / อื่น ๆ
  ถ้าเลือก "อื่น ๆ" ต้องมีข้อความที่ผู้ขอพิมพ์ระบุเก็บคู่กัน,
  เวลาที่ส่ง (ใช้เรียงลำดับคำขอที่มาก่อน DOM-REQ-01)
  ฟิลด์อื่นเจ้าของ 002 เป็นผู้เสนอใน spec ของตน ใช้โดย UC-02, UC-05, UC-06, UC-12, UC-14, UC-15
- DM-07 AuditLog (`audit_log`): ผู้เข้าถึง บทบาท เวลา การกระทำ เงื่อนไขที่ค้น รหัสครุภัณฑ์ (ว่างได้)
  รหัสคำขอยืม (`request_id` ว่างได้ เพิ่มตามคำขอของ 003 2569-11-10) ผลลัพธ์ (DOM-AUDIT-01, RQ-25) append-only
  ค่าของการกระทำ (`action`) ที่ตกลงแล้ว:
  | action | ฟีเจอร์ | ความหมาย |
  |---|---|---|
  | `list`, `search`, `detail` | 001 | ดูรายการ ค้นหา เปิดรายละเอียดอุปกรณ์ |
  | `cancel` | 003 | นักศึกษายกเลิกคำขอยืม |
  | `request` | 002 | นักศึกษาส่งคำขอยืม (ใช้ค่าเดียวทั้งยืมปกติและค้างคืน ประเภทอยู่ใน DM-06
    ผลของการถูกปฏิเสธแยกด้วยคอลัมน์ outcome) ทีมตกลง 2569-11-11 เพิ่มค่าใน CHECK ด้วย migration 0003 ของ 002 |
  | `notify` | 003 (ฟีเจอร์อื่นใช้ร่วมได้ เช่น 004 RQ-21) | ส่งการแจ้งเตือน (IF-NOT-01) บันทึกเมื่อส่งไม่สำเร็จ outcome `error` |
  | `return_list`, `return_lookup`, `return_detail` | 006 | เจ้าหน้าที่เปิดรายการที่ยังไม่คืน ค้นการยืมจากรหัสครุภัณฑ์ เปิดรายละเอียดการยืม |
  | `return` | 006 | เจ้าหน้าที่บันทึกการรับคืน (เพิ่มใน CHECK ด้วย migration 0010 โดยคงค่าของทุกฟีเจอร์) |
  ฟีเจอร์อื่นที่ต้องการค่าใหม่ ให้เพิ่มแถวในตารางนี้และเพิ่มค่าใน CHECK ด้วย migration ใหม่ (ห้ามแก้ migration เดิม)
  `cancel_notify_failed` ที่ 003 ขอไว้เดิม เปลี่ยนเป็น `notify` (2569-11-11 ASM-12 ของ 003) เพิ่มใน CHECK ด้วย migration ของ 003
  `request_id` มี foreign key ไป `borrow_request (id)` แล้ว 002 เพิ่มใน migration 0003 (2569-11-11)

## สถานะอุปกรณ์ (CON-DATA-01) ชื่อในโค้ด
| สถานะ (spec) | ค่าในฐานข้อมูล | ความหมาย |
|---|---|---|
| ว่าง | `available` | ยืมได้ (คำว่า "พร้อมให้ยืม" ใน RQ-13 และ US-010 หมายถึงสถานะนี้) |
| ถูกยืม | `borrowed` | มี Loan ที่ยังไม่คืน |
| ไม่พร้อมใช้งาน | `unavailable` | ชำรุด ส่งซ่อม สูญหาย หรือเหตุอื่นที่เจ้าหน้าที่กำหนด |

## สถานะของคำขอยืม (แยกจากสถานะอุปกรณ์)
ยืนยันโดยเจ้าของ 002 เมื่อ 2569-11-11 (ปิด Q-BRQ-08) อ้างอิง workflow ใน Infrastructure บน Miro และ RQ-03 (UC-15)
**กระทบ 003, 004, 005, 006 ที่ใช้สถานะเดียวกัน**

ชื่อสถานะกับค่าที่เก็บจริงแยกกันเหมือนตารางสถานะอุปกรณ์ (CON-DATA-01) ด้านล่าง
ค่าในฐานข้อมูลเป็นตัวพิมพ์เล็กคั่นด้วย `_` ให้เข้าชุดกับค่าอื่นในระบบ (`available`, `normal`, `list`)
ทีมตัดสิน 2569-11-11 หลังเจ้าของ 003 เสนอ

| # | สถานะของคำขอ (spec) | ค่าในฐานข้อมูล | ความหมาย | ใช้กับ | ตั้งค่าโดย |
|---|---|---|---|---|---|
| 1 | Requested | `requested` | ส่งแล้ว รออนุมัติ | ปกติ, ค้างคืน | UC-02 / UC-05 (002) |
| 2 | Approved by Officer | `approved_by_officer` | เจ้าหน้าที่ผ่านขั้นแรกแล้ว | ค้างคืนเท่านั้น | UC-12 (004) |
| 3 | Pending Advisor Approval | `pending_advisor_approval` | รออาจารย์หัวหน้าโครงการเซ็น (นอกระบบ) | ค้างคืนเท่านั้น | UC-11 / UC-14 |
| 4 | Approved | `approved` | อนุมัติแล้ว | ปกติ, ค้างคืน | UC-12 / UC-14 (004) |
| 5 | Rejected | `rejected` | ปฏิเสธ | ปกติ, ค้างคืน | UC-12 / UC-14 (004) |
| 6 | Handed Over | `handed_over` | ส่งมอบอุปกรณ์แล้ว | ปกติ, ค้างคืน | UC-08 (005) |
| 7 | Returned | `returned` | คืนอุปกรณ์แล้ว | ปกติ, ค้างคืน | UC-09 (006) |
| 8 | Cancelled | `cancelled` | ถูกยกเลิกแล้ว (UC-15, RQ-03) | ปกติ, ค้างคืน | UC-15 (003) |

002 เป็นผู้ประกาศค่าทั้ง 8 ใน CHECK ของตาราง `borrow_request` ตั้งแต่ migration 0003 (ปิด Q-BRQ-09)
คอลัมน์ `cancel_reason` (VARCHAR 200 ว่างได้) และ `cancelled_at` (TIMESTAMPTZ ว่างได้) เป็นของ 003
002 สร้างให้ใน 0003 แต่ไม่เขียนค่าเอง (ขอโดยเจ้าของ 003 และ**ยืนยันชนิดข้อมูลแล้ว** 2569-11-11)
ฟีเจอร์นี้ (002) ตั้งได้เฉพาะค่า `Requested` เท่านั้น การเปลี่ยนสถานะอื่นเป็นของฟีเจอร์ตามคอลัมน์ "ตั้งค่าโดย"
