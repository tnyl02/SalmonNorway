# ข้อมูลที่หลายฟีเจอร์ใช้ร่วมกัน (shared data model)
Status: v4 | Updated: 2569-11-10 (DM-07 เพิ่ม request_id และ action ตามคำขอของ 003) | Source: plan.md ข้อ 4 ของ 001, Infrastructure บน Miro

เขียนเฉพาะสิ่งที่มากกว่า 1 ฟีเจอร์ใช้ ฟิลด์ที่ใช้เฉพาะฟีเจอร์เดียว ไปอยู่ใน plan.md ของฟีเจอร์นั้น
ชื่อตารางในวงเล็บคือชื่อใน PostgreSQL (CON-TECH-01)

- DM-01 Department ภาควิชา (`department`): รหัส ชื่อ
- DM-02 Category ประเภทอุปกรณ์ (`category`): รหัส ชื่อ (ตายตัวหรือเพิ่มได้ รอ Q-04 ของ 001)
- DM-03 EquipmentModel รุ่น/ชนิด (`equipment_model`): ชื่อรุ่น ประเภท ภาควิชาเจ้าของ
- DM-04 EquipmentItem อุปกรณ์รายชิ้น (`equipment_item`): รหัสครุภัณฑ์ไม่ซ้ำ (CON-DATA-03), รุ่น,
  สถานะ 1 ใน 3 ค่า (CON-DATA-01), เวลาที่สถานะเปลี่ยนล่าสุด
- DM-05 Loan การยืม (`loan`): อุปกรณ์รายชิ้น ผู้ยืม ประเภทการยืม (ปกติ / ค้างคืน)
  กำหนดคืน (**วันที่และเวลา** ยืมปกติ = 16:00 วันเดียวกัน ตาม DOM-LOAN-01, ค้างคืนรอ Q-SH-04) เวลาคืน (ว่าง = ยังไม่คืน)
  สร้างโดย UC-08 ปิดโดย UC-09
  ฟิลด์ตอนรับคืน (เพิ่มโดย 006 ใน `0006_return.up.sql` ว่างได้ทั้งหมด ไม่กระทบ 001, 005): สภาพตอนรับคืน (`return_condition` ปกติ / ชำรุด FR-RET-02),
  คืนเกินกำหนด (`returned_late` FR-RET-06) คืนแล้วต้องมีครบทั้งเวลาคืน สภาพ และคืนเกินกำหนด
- DM-06 BorrowRequest คำขอยืม (`borrow_request`): ประเภท (ปกติ / ค้างคืน), วัตถุประสงค์ (RQ-18), สถานะของคำขอ,
  เวลาที่ส่ง (ใช้เรียงลำดับคำขอที่มาก่อน DOM-REQ-01)
  ฟิลด์อื่นเจ้าของ 002 เป็นผู้เสนอใน spec ของตน ใช้โดย UC-02, UC-05, UC-06, UC-12, UC-14, UC-15
- DM-07 AuditLog (`audit_log`): ผู้เข้าถึง บทบาท เวลา การกระทำ เงื่อนไขที่ค้น รหัสครุภัณฑ์ (ว่างได้)
  รหัสคำขอยืม (`request_id` ว่างได้ เพิ่มตามคำขอของ 003 2569-11-10) ผลลัพธ์ (DOM-AUDIT-01, RQ-25) append-only
  ค่าของการกระทำ (`action`) ที่ตกลงแล้ว:
  | action | ฟีเจอร์ | ความหมาย |
  |---|---|---|
  | `list`, `search`, `detail` | 001 | ดูรายการ ค้นหา เปิดรายละเอียดอุปกรณ์ |
  | `cancel` | 003 | นักศึกษายกเลิกคำขอยืม |
  | `return_list`, `return_lookup`, `return_detail` | 006 | เจ้าหน้าที่เปิดรายการที่ยังไม่คืน ค้นการยืมจากรหัสครุภัณฑ์ เปิดรายละเอียดการยืม |
  | `return` | 006 | เจ้าหน้าที่บันทึกการรับคืน |
  ฟีเจอร์อื่นที่ต้องการค่าใหม่ ให้เพิ่มแถวในตารางนี้และเพิ่มค่าใน CHECK ด้วย migration ใหม่ (ห้ามแก้ migration เดิม)
  `cancel_notify_failed` ที่ 003 ขอไว้ รอทีมตัดสินว่าการแจ้งเตือน (BL-21, Should) อยู่ใน prototype ไหม
  `request_id` ยังไม่มี foreign key เพราะตาราง `borrow_request` (DM-06) ยังไม่มี ให้ 002 เพิ่ม FK ตอนสร้างตาราง

- DM-08 Principal ผู้ใช้ที่ยืนยันตัวตนแล้ว (ไม่มีตาราง ได้จาก IF-IDP-01): รหัสผู้ใช้ บทบาท (นักศึกษา / เจ้าหน้าที่) ภาควิชา

## สถานะอุปกรณ์ (CON-DATA-01) ชื่อในโค้ด
| สถานะ (spec) | ค่าในฐานข้อมูล | ความหมาย |
|---|---|---|
| ว่าง | `available` | ยืมได้ (คำว่า "พร้อมให้ยืม" ใน RQ-13 และ US-010 หมายถึงสถานะนี้) |
| ถูกยืม | `borrowed` | มี Loan ที่ยังไม่คืน |
| ไม่พร้อมใช้งาน | `unavailable` | ชำรุด ส่งซ่อม สูญหาย หรือเหตุอื่นที่เจ้าหน้าที่กำหนด |

## สถานะของคำขอยืม (แยกจากสถานะอุปกรณ์)
ร่างจาก workflow ใน Infrastructure บน Miro: Requested -> Approved by Officer -> (ค้างคืน) Pending Advisor Approval -> Approved / Rejected -> Handed Over -> Returned
เพิ่ม "ยกเลิก" จาก RQ-03 (UC-15) ชื่อสถานะจริงให้เจ้าของ 002 ยืนยันใน spec ของตน
