## Goal
เจ้าหน้าที่บันทึกการส่งมอบอุปกรณ์ให้ผู้ยืมในระบบได้ โดยระบบตรวจตัวตนผู้ยืมและความพร้อมของอุปกรณ์ก่อนทุกครั้ง
แล้วบันทึกเวลาที่ยืมและกำหนดคืน เพื่อให้สถานะอุปกรณ์เป็น "ถูกยืม" และนักศึกษาเห็นกำหนดคืนใน UC-01 (BL-09)
แทนการเขียนข้อมูลการยืมด้วยมือที่ตรวจสอบย้อนหลังยาก (Journey Map)

## Scope
### In scope
- ดูรายการคำขอยืมที่ได้รับอนุมัติแล้วและยังไม่ส่งมอบ แล้วเลือกคำขอเพื่อบันทึกการส่งมอบ
- ยืนยันตัวตนผู้ยืมผ่าน Auth API และตรวจบัตรทุกครั้ง (RQ-19, RQ-23)
- ตรวจสถานะอุปกรณ์รายชิ้นก่อนสร้างการยืม (RQ-08)
- บันทึกวันเวลาที่ส่งมอบ และกำหนดคืนของการยืมแบบปกติ (RQ-17, DOM-LOAN-01)
- แนบรูปภาพสภาพอุปกรณ์ตอนส่งมอบ (RQ-04)
- สร้างการยืม (Loan) เปลี่ยนสถานะอุปกรณ์เป็น "ถูกยืม" และเปลี่ยนสถานะของคำขอที่ส่งมอบ
- บันทึก audit log ของการส่งมอบ (RQ-25)
- การยืมแบบค้างคืน: FR ครอบคลุมแล้ว แต่กำหนดคืนรอ Q-SH-04 และ prototype ไม่มีคำขอค้างคืน (UC-05, UC-14 ไม่ทำ) ดู Q-HND-07
### Out of scope
- ส่งคำขอยืม (UC-02, UC-05) | ยกเลิกคำขอ (UC-15) | อนุมัติคำขอ (UC-12) และบันทึกผลอนุมัติค้างคืน (UC-14)
- นักศึกษายืนยันรับอุปกรณ์ (UC-03, BL-12 Could เลื่อนไว้ก่อน)
- บันทึกการรับคืน (UC-09) และตรวจสอบอุปกรณ์ที่คืน (UC-07)
- แจ้งเตือนใกล้ถึงกำหนดคืน (RQ-12) | บทลงโทษเมื่อคืนเกินกำหนด (RQ-27, Q-SH-07)
- จัดการรายการอุปกรณ์ (UC-10) | จองอุปกรณ์ล่วงหน้า (BL-11 Won't ตาม N-01)
- เจ้าหน้าที่เลือกหรือเปลี่ยนอุปกรณ์รายชิ้นตอนส่งมอบ (คำขอระบุรายชิ้นมาแล้ว ASM-HND-03)
- เปลี่ยนสถานะหรือแจ้งผู้ส่งคำขออื่นของอุปกรณ์ชิ้นเดียวกัน (เจ้าหน้าที่ปฏิเสธเองผ่าน UC-12 ASM-HND-08)

## Constraints
ใช้ร่วม (ข้อความเต็มอยู่ที่ specs/000-shared/constraints.md ห้าม copy มาไว้ที่นี่):
- CON-TECH-01 ฐานข้อมูล PostgreSQL
- CON-TECH-02 HTTPS เท่านั้น deploy ด้วย Docker
- CON-DATA-01 สถานะอุปกรณ์ 3 ค่าเท่านั้น: ว่าง, ถูกยืม, ไม่พร้อมใช้งาน
- CON-DATA-03 รหัสครุภัณฑ์ไม่ซ้ำกัน
- DOM-AUDIT-01 audit log ทุกครั้งที่เข้าถึงข้อมูลอุปกรณ์
- DOM-LOAN-01 ยืมแบบปกติคืนภายใน 16:00 น. วันเดียวกัน
- DOM-REQ-01 อุปกรณ์ที่มีคำขอยืมค้างยังมีสถานะ "ว่าง" (สถานะเปลี่ยนเป็น "ถูกยืม" ที่ฟีเจอร์นี้)
- IF-IDP-01 ต้องยืนยันตัวตนผ่านระบบยืนยันตัวตนของมหาวิทยาลัยก่อน
เฉพาะฟีเจอร์นี้:
- CON-HND-01 ผู้บันทึกการส่งมอบได้คือบทบาทเจ้าหน้าที่เท่านั้น (actor ของ UC-08 ใน Use Case Diagram) ควรย้ายไปไฟล์ร่วมไหม รอ Q-HND-15

## Requirements
- FR-HND-01 ระบบต้องแสดงรายการคำขอยืมที่ได้รับอนุมัติแล้วและยังไม่ส่งมอบทั้งหมดให้เจ้าหน้าที่ เพื่อเลือกคำขอที่จะบันทึกการส่งมอบ
  และบันทึกการส่งมอบได้เฉพาะคำขอที่ได้รับอนุมัติแล้ว (ยืมแบบปกติจาก UC-12, ยืมแบบค้างคืนจาก UC-14)
                                                                      <- RQ-14, RQ-15, workflow ใน Infrastructure, ASM-HND-05
- FR-HND-02 ก่อนบันทึกการส่งมอบ ระบบต้องยืนยันตัวตนผู้ยืมผ่าน Auth API ของมหาวิทยาลัย
  ถ้าไม่ได้ผลภายใน 10 วินาที ถือว่าเชื่อมต่อไม่สำเร็จ ให้ใช้ผลการตรวจบัตรตาม FR-HND-03 แทน
  ผู้ยืมที่ยืนยันตัวตนต้องเป็นผู้ส่งคำขอนั้น ถ้าไม่ใช่ ระบบต้องปฏิเสธการส่งมอบ
  (วิธียืนยันตัวตนผู้ยืมที่เคาน์เตอร์ รอ Q-HND-11)                        <- RQ-23, IF-IDP-01, ASM-HND-02, ASM-HND-04
- FR-HND-03 เจ้าหน้าที่ต้องตรวจบัตรนักศึกษาหรือบัตรประชาชนของผู้ยืมก่อนส่งมอบทุกครั้ง (รวมถึงเมื่อ Auth API ยืนยันสำเร็จ)
  และระบบต้องบันทึกชื่อ นามสกุล รหัสนักศึกษาของผู้ยืม และวันที่และเวลาที่ส่งมอบ
  (ชื่อและนามสกุลได้มาจากไหน รอ Q-HND-13)                              <- RQ-19, ASM-HND-01
- FR-HND-04 ระบบต้องตรวจว่าอุปกรณ์รายชิ้นในคำขอมีสถานะ "ว่าง" ก่อนสร้างการยืมทุกครั้ง
  ถ้าไม่ใช่ "ว่าง" ต้องไม่สร้างการยืม                                   <- RQ-08, CON-DATA-01
- FR-HND-05 ระบบต้องบันทึกวันที่และเวลาที่ส่งมอบตามเวลาจริง (Asia/Bangkok) และกำหนดคืน (วันที่และเวลา)
  ยืมแบบปกติ: กำหนดคืน = 16:00 น. ของวันที่ส่งมอบ (DOM-LOAN-01)
  ระบบบันทึกการส่งมอบหลัง 16:00 น. ได้ (กำหนดคืนของกรณีนี้รอ Q-HND-03)
  ยืมแบบค้างคืน: รอ Q-SH-04                                            <- RQ-17, ASM-HND-06
- FR-HND-06 ระบบต้องให้เจ้าหน้าที่แนบรูปภาพสภาพอุปกรณ์ในขั้นตอนส่งมอบ ทั้งยืมแบบปกติและแบบค้างคืน
  บังคับอย่างน้อย 2 รูป ไฟล์ JPG หรือ PNG ขนาดไม่เกิน 10 MB (ต่อรูปหรือรวม รอ Q-HND-10)
  ถ้าไม่ครบตามนี้ ระบบต้องไม่บันทึกการส่งมอบ                             <- RQ-04, ASM-HND-07
- FR-HND-07 เมื่อบันทึกการส่งมอบสำเร็จ ระบบต้องสร้างการยืม (Loan) เปลี่ยนสถานะอุปกรณ์จาก "ว่าง" เป็น "ถูกยืม"
  และเปลี่ยนสถานะของคำขอเป็น "ส่งมอบแล้ว" (ชื่อสถานะรอ Q-HND-05)
  ระบบไม่เปลี่ยนคำขอยืมอื่นของอุปกรณ์ชิ้นเดียวกัน (ASM-HND-08)
                                                                      <- RQ-17, DM-05, DOM-REQ-01, data-model.md ตาราง "ใครเปลี่ยนสถานะอุปกรณ์"
- FR-HND-08 ระบบต้องบันทึก audit log ของการส่งมอบ ระบุผู้ทำ เวลา รหัสครุภัณฑ์ รหัสคำขอยืม และผลลัพธ์
  (บันทึกกรณีไม่สำเร็จด้วยไหม รอ Q-HND-14)                              <- RQ-25, DOM-AUDIT-01, DM-07

## Quality Requirements
- NFR-SEC-01 ข้อมูลเข้ารหัสขณะรับส่งด้วย TLS 1.2 ขึ้นไป และต้องผ่านการยืนยันตัวตนก่อนทุกครั้ง (SRS หัวข้อ 3.3)
- NFR-AVAIL-01 ระบบพร้อมใช้งานอย่างน้อย 99% ในช่วง 08.30-16.30 น. วันจันทร์-ศุกร์ (SRS หัวข้อ 3.3)
- เวลาตอบสนองของการบันทึกการส่งมอบ: ไม่มีใน RQ หรือ SRS รอ Q-HND-09

## Acceptance Criteria
- [ ] AC-HND-01 (FR-HND-01)
      Given คำขอยืมแบบปกติที่ยังไม่ได้รับอนุมัติ และอุปกรณ์รายชิ้นในคำขอมีสถานะ "ว่าง"
      When  เจ้าหน้าที่บันทึกการส่งมอบของคำขอนั้น
      Then  ระบบไม่บันทึกการส่งมอบ ไม่มี Loan ถูกสร้าง และอุปกรณ์ยังมีสถานะ "ว่าง"
- [ ] AC-HND-02 (FR-HND-02, FR-HND-03)
      Given คำขอยืมแบบปกติที่ได้รับอนุมัติแล้ว Auth API ยืนยันตัวตนผู้ยืมสำเร็จ และผู้ยืมเป็นผู้ส่งคำขอ
      When  เจ้าหน้าที่ยืนยันว่าตรวจบัตรแล้ว และบันทึกการส่งมอบ
      Then  ระบบบันทึกการส่งมอบ พร้อมชื่อ นามสกุล รหัสนักศึกษาของผู้ยืม และวันที่และเวลาที่ส่งมอบ
            ถ้าเจ้าหน้าที่ไม่ยืนยันการตรวจบัตร ระบบไม่บันทึกการส่งมอบ
- [ ] AC-HND-03 (FR-HND-02, FR-HND-03)
      Given คำขอยืมแบบปกติที่ได้รับอนุมัติแล้ว และ Auth API ไม่ตอบภายใน 10 วินาที
      When  เจ้าหน้าที่ยืนยันว่าตรวจบัตรแล้ว และบันทึกการส่งมอบ
      Then  ระบบบันทึกการส่งมอบได้โดยใช้ผลการตรวจบัตร
            ถ้าเจ้าหน้าที่ไม่ยืนยันการตรวจบัตร ระบบไม่บันทึกการส่งมอบ

      Given คำขอยืมแบบปกติที่ได้รับอนุมัติแล้ว แต่อุปกรณ์รายชิ้นในคำขอมีสถานะ "ไม่พร้อมใช้งาน" หรือ "ถูกยืม"
      When  เจ้าหน้าที่บันทึกการส่งมอบ
      Then  ระบบไม่สร้างการยืม และสถานะอุปกรณ์ไม่เปลี่ยน
- [ ] AC-HND-05 (FR-HND-05, DOM-LOAN-01)
      Given คำขอยืมแบบปกติที่ได้รับอนุมัติแล้ว
      When  เจ้าหน้าที่บันทึกการส่งมอบสำเร็จเมื่อ 2569-11-12 เวลา 10:00 น. (Asia/Bangkok)
      Then  การยืมนั้นมีเวลาที่ส่งมอบ 2569-11-12 10:00 น. และกำหนดคืน 2569-11-12 16:00 น.

      Given คำขอยืมแบบปกติที่ได้รับอนุมัติแล้ว
      When  เจ้าหน้าที่แนบรูปสภาพอุปกรณ์ JPG 2 รูป ขนาดรูปละ 2 MB แล้วบันทึกการส่งมอบ
      Then  ระบบบันทึกการส่งมอบ และรูปทั้ง 2 รูปถูกบันทึกผูกกับการยืมนั้น
- [ ] AC-HND-07 (FR-HND-07, DOM-REQ-01)
      Given คำขอยืมแบบปกติที่ได้รับอนุมัติแล้ว อุปกรณ์รายชิ้นมีสถานะ "ว่าง" และยืนยันตัวตนผู้ยืมแล้ว
      When  เจ้าหน้าที่บันทึกการส่งมอบ
      Then  มี Loan ใหม่ 1 รายการของผู้ยืมและอุปกรณ์ชิ้นนั้น ที่ยังไม่มีเวลาคืน
            สถานะอุปกรณ์เป็น "ถูกยืม" และสถานะของคำขอเป็น "ส่งมอบแล้ว"
            (การแสดงผลใน UC-01 ตรวจโดย AC-EQS-04 ของ 001)
- [ ] AC-HND-08 (FR-HND-08)
      Given เจ้าหน้าที่บันทึกการส่งมอบ (ทั้งสำเร็จและไม่สำเร็จ รอ Q-HND-14)
      When  การบันทึกเสร็จสิ้น
      Then  มี audit log ที่ระบุผู้ทำ เวลา รหัสครุภัณฑ์ รหัสคำขอยืม และผลลัพธ์
- [ ] AC-HND-09 (CON-HND-01)
      Given ผู้ใช้บทบาทนักศึกษายืนยันตัวตนแล้ว

      Then  ระบบปฏิเสธ ไม่มี Loan ถูกสร้าง และสถานะอุปกรณ์ไม่เปลี่ยน
- [ ] AC-HND-10 (FR-HND-02)
      Given คำขอยืมแบบปกติที่ได้รับอนุมัติแล้วของนักศึกษา A

      Then  ระบบปฏิเสธการส่งมอบ ไม่มี Loan ถูกสร้าง และอุปกรณ์ยังมีสถานะ "ว่าง"

      When  เจ้าหน้าที่บันทึกการส่งมอบเมื่อ 2569-11-12 เวลา 16:30 น. (Asia/Bangkok)
      Then  ระบบบันทึกการส่งมอบ การยืมนั้นมีเวลาที่ส่งมอบ 2569-11-12 16:30 น. และอุปกรณ์มีสถานะ "ถูกยืม"

      Given คำขอยืมแบบปกติที่ได้รับอนุมัติแล้ว
      When  เจ้าหน้าที่บันทึกการส่งมอบโดยแนบรูป (ก) 1 รูป หรือ (ข) ไฟล์ GIF หรือ (ค) รูปขนาด 11 MB
      Then  ระบบไม่บันทึกการส่งมอบในทุกกรณี และไม่มี Loan ถูกสร้าง

      Given อุปกรณ์รายชิ้นหนึ่งมีคำขอยืม 2 รายการ คำขอ X ได้รับอนุมัติแล้ว และคำขอ Y ยังไม่ได้ตัดสิน
