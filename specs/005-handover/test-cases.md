อ้างอิง: spec.md SPEC-HND-005 Draft v2.8 | plan.md v1.5 ข้อ 4 (สัญญา API) และข้อ 6 | tasks.md v1.5

คนออกแบบตารางนี้ AI เขียนโค้ด test ตามตารางด้วยคำสั่ง /testcases
- สถานะ: ร่าง (AI เสนอ ยังไม่มีใครตรวจ) / ใช้ได้ (ทีมตรวจแล้ว) / รอ Q-xx
- test ที่มาจากตารางนี้ (ชื่อขึ้นต้น `TestTC_` หรือไฟล์ `TC-*.test.jsx`) ห้ามแก้ให้ผ่าน ถ้าไม่ผ่าน ต้องหาว่าโค้ดผิด หรือ AC ผิด (ถ้า AC ผิด แก้ spec ก่อน)
- ทีมใช้ Go (AGENTS.md): ช่อง "ตรวจด้วย" ใช้ `go test` แทน pytest ชื่อ test หลังบ้านเป็น `TestTC_HND_<AC>_<ลำดับ>_<ชื่อ>` อยู่ในไฟล์ `*_test.go` ของ `backend/internal/handover/`
  test หน้าจอใช้ vitest ชื่อไฟล์ `TC-HND-<AC>-<ลำดับ>.test.jsx` ใน `frontend/src/__tests__/` ใช้ client จำลองแทนหลังบ้าน
- ข้อมูลในตาราง: test หลังบ้านสร้างข้อมูลเองต่อ test (แบบ `createItem` / `createRequest` ใน handler_test.go) แถว "คน" ใช้ `backend/db/seed/handover_dev.sql`
  - เจ้าหน้าที่ = staff-001 (token `mock-staff-001`) / นักศึกษา A = student-001 (`mock-student-001`) / นักศึกษา B = student-101 (`mock-student-101`) จาก `auth.MockProvider`
  - "ข้อมูลส่งมอบครบ" = `borrowerCredential` ของผู้ส่งคำขอ, ชื่อและนามสกุลตามบัตร (ASM-HND-10), `cardChecked=true`, รูป JPG 2 รูป รูปละไม่เกิน 10 MB
  - "ว่าง" = `equipment_item.status = 'available'` "ถูกยืม" = `borrowed` "ไม่พร้อมใช้งาน" = `unavailable` (CON-DATA-01) "อนุมัติแล้ว" = `borrow_request.status = 'approved'` "ส่งมอบแล้ว" = `handed_over` (data-model v9)
  - เวลาเป็น Asia/Bangkok (FR-HND-05) test ที่ขึ้นกับเวลาใช้นาฬิกาจำลองของ service (`routesAt`) test ที่ขึ้นกับ timeout ใช้ `WithTimeout` ค่าสั้นแทน 10 วินาที (plan ข้อ 6)
- ยืมค้างคืน (T-30) ไม่มี AC ใน spec จึงไม่มีแถวในตารางนี้ (ตรวจด้วย `TestHandover_OvernightDueAt` ดู plan ข้อ 6)
