## Goal
นักศึกษาที่ยืนยันตัวตนแล้ว ส่งคำขอยืมอุปกรณ์ที่ว่างได้ด้วยตนเองจากหน้าอุปกรณ์ โดยไม่ต้องเขียนเอกสารด้วยมือ
และระบบตรวจความพร้อมของอุปกรณ์กับสิทธิ์ของผู้ขอให้ก่อนสร้างคำขอ ทำให้คำขอทุกรายการมีผู้ขอและเวลาที่ส่งซึ่งตรวจสอบย้อนหลังได้

## Scope
### In scope
- ส่งคำขอยืมอุปกรณ์ที่สถานะ "ว่าง" พร้อมตรวจสถานะซ้ำทั้งตอนเปิดฟอร์มและตอนกดส่ง
- แบบฟอร์มคำขอ: ประเภทการยืม (ปกติ / ค้างคืน), วัตถุประสงค์, ช่วงเวลาที่ต้องการยืม และการตรวจความครบถ้วนก่อนส่ง
- การยืมแบบค้างคืน (UC-05): ระบุเหตุผลและแนบเอกสารประกอบ (ใบบันทึกข้อความ) ตาม RQ-16
- ปฏิเสธคำขอใหม่อัตโนมัติเมื่อผู้ขอมีอุปกรณ์คืนเกินกำหนดค้างอยู่ (RQ-20)
- รองรับคำขอซ้อนบนอุปกรณ์ชิ้นเดียวกัน พร้อมแสดงเวลาที่ส่งและลำดับของคำขอที่มาก่อน (DOM-REQ-01)
- จำกัดการส่งคำขอเฉพาะอุปกรณ์ของภาควิชาผู้ขอ (DOM-ACCESS-01)
- บันทึก audit log ของการส่งคำขอ ทั้งกรณีสำเร็จและถูกปฏิเสธ (DOM-AUDIT-01, RQ-25)
### Out of scope
- อนุมัติหรือปฏิเสธคำขอ และแจ้งผลให้ผู้ขอ (UC-12, RQ-14, RQ-21 -> 004)
- ตรวจเอกสารขออนุมัติค้างคืนและบันทึกผลที่อาจารย์เซ็นนอกระบบ (UC-11, UC-14, RQ-15 -> BL-17, 004)
  ฟีเจอร์นี้ครอบคลุมเฉพาะการ**ส่ง**คำขอค้างคืนเท่านั้น
- ยกเลิกคำขอยืม (UC-15, RQ-03 -> 003) | ตรวจสอบสถานะคำขอของตนเอง (UC-06, RQ-10 -> BL-15)
- บันทึกการส่งมอบและกำหนดคืน (UC-08, RQ-17 -> 005) | บันทึกการรับคืน (UC-09 -> 006)
- เปลี่ยนสถานะอุปกรณ์ (ฟีเจอร์นี้ไม่เปลี่ยนสถานะใด ๆ ดูตาราง "ใครเปลี่ยนสถานะอุปกรณ์" ใน specs/000-shared/data-model.md)
- ยืนยันตัวตน (IF-IDP-01) ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition ของ UC-02)

## Constraints
ใช้ร่วม (ข้อความเต็มอยู่ที่ specs/000-shared/constraints.md ห้าม copy มาไว้ที่นี่):
- CON-TECH-01 ฐานข้อมูล PostgreSQL
- CON-TECH-02 HTTPS เท่านั้น deploy ด้วย Docker
- CON-DATA-01 สถานะอุปกรณ์ 3 ค่าเท่านั้น (ฟีเจอร์นี้ส่งคำขอได้เฉพาะชิ้นที่สถานะ "ว่าง")
- CON-DATA-03 รหัสครุภัณฑ์ไม่ซ้ำกัน (ใช้ระบุอุปกรณ์ที่ขอยืม)
- DOM-PRIV-01 นักศึกษาไม่เห็นชื่อผู้ยืมหรือผู้ขอรายอื่น (กระทบการแสดงลำดับคำขอใน FR-BRQ-05)
- DOM-AUDIT-01 audit log ทุกครั้งที่เข้าถึงข้อมูลอุปกรณ์
- DOM-ACCESS-01 นักศึกษาเข้าถึงได้เฉพาะอุปกรณ์ภาควิชาของตนเอง
- DOM-LOAN-01 ยืมแบบปกติคืนภายใน 16:00 น. วันเดียวกัน และใช้งานในพื้นที่มหาวิทยาลัย (ไม่ใช้กับค้างคืน)
- DOM-REQ-01 อุปกรณ์ที่มีคำขอยืมค้างยังมีสถานะ "ว่าง" ส่งซ้อนได้ ต้องแสดงเวลาและลำดับของคำขอที่มาก่อน
- IF-IDP-01 ต้องยืนยันตัวตนผ่านระบบของมหาวิทยาลัยก่อน และได้ภาควิชาของผู้ใช้กลับมา
เฉพาะฟีเจอร์นี้:
- ยังไม่มี Constraint เฉพาะฟีเจอร์นี้ ข้อตกลงทางเทคนิคกับ 001 (เลข migration และชนิดของ id) อยู่ที่ ASM-BRQ-03
  เพราะเป็นข้อตกลงระหว่างทีม ไม่ใช่ข้อกำหนดจากผู้ใช้

## Requirements
ID ตรงกับ docs/srs/SRS.md หัวข้อ 3.1.2 ทุกข้อ ห้ามเปลี่ยนเลข

- FR-BRQ-01 ระบบต้องให้ผู้ขอส่งคำขอยืมอุปกรณ์รายชิ้นที่สถานะ "ว่าง" โดยรับรหัสครุภัณฑ์จาก FR-EQS-06
  และต้องตรวจสถานะอุปกรณ์ซ้ำทั้งตอนเปิดฟอร์มและตอนกดส่ง
  ถ้าสถานะไม่ใช่ "ว่าง" แล้ว ต้องไม่สร้างคำขอ และแจ้งสถานะล่าสุด     <- US-002, FR-EQS-06, UC-02 main flow 1-2, exception 2a
- FR-BRQ-02 แบบฟอร์มคำขอต้องให้ผู้ขอระบุวัตถุประสงค์การยืมแบบแยกประเภท
  (เช่น เพื่อการเรียน, เพื่อทำกิจกรรม) และเก็บไว้กับคำขอ              <- RQ-18, UC-02 main flow 5, DM-06
- FR-BRQ-03 ระบบต้องตรวจความครบถ้วนของข้อมูลในฟอร์มก่อนอนุญาตให้ส่ง ถ้าไม่ครบ ต้องไม่สร้างคำขอ
  และระบุช่องที่ยังขาด ข้อมูลที่ต้องครบรวม "ช่วงเวลาที่ต้องการยืม" ด้วย  <- RQ-22, UC-02 main flow 6 และ 9, exception 9a
- FR-BRQ-04 เมื่อส่งสำเร็จ ระบบต้องสร้างคำขอยืมด้วยสถานะเริ่มต้น "รออนุมัติ"
  พร้อมบันทึกผู้ขอ อุปกรณ์รายชิ้น ประเภทการยืม และเวลาที่ส่ง (Asia/Bangkok)
  และต้องไม่เปลี่ยนสถานะอุปกรณ์                                     <- UC-02 postcondition, main flow 10, DM-06, DOM-REQ-01
- FR-BRQ-05 ระบบต้องอนุญาตให้ส่งคำขอซ้อนกับคำขอที่ค้างอยู่ของผู้อื่นบนอุปกรณ์ชิ้นเดียวกัน
  และแสดงเวลาที่ส่งกับลำดับของคำขอที่มาก่อน                          <- DOM-REQ-01 (แสดงให้ใครเห็นและที่หน้าไหน รอ Q-SH-05)
- FR-BRQ-06 ระบบต้องปฏิเสธคำขอใหม่โดยอัตโนมัติเมื่อผู้ขอมีอุปกรณ์ที่คืนเกินกำหนดค้างอยู่ในระบบ
  พร้อมแจ้งเหตุผล และไม่สร้างคำขอ                                   <- RQ-20, UC-02 precondition 3, main flow 3, exception 3a
- FR-BRQ-07 ระบบต้องอนุญาตให้นักศึกษาส่งคำขอได้เฉพาะอุปกรณ์ของภาควิชาตนเอง
  คำขอข้ามภาควิชาต้องถูกปฏิเสธ และผู้ขอต้องไม่ได้รับข้อมูลอุปกรณ์      <- DOM-ACCESS-01, FR-EQS-10
- FR-BRQ-08 ระบบต้องบันทึก audit log ทุกครั้งที่มีการส่งคำขอ ทั้งกรณีสำเร็จและถูกปฏิเสธ
  ระบุผู้ขอ เวลา รหัสครุภัณฑ์ และผลลัพธ์                              <- DOM-AUDIT-01, RQ-25, UC-02 main flow 11, DM-07
- FR-BRQ-09 เมื่อบันทึกคำขอไม่สำเร็จหลังกดส่ง (ระบบหรือฐานข้อมูลขัดข้อง) ระบบต้องแจ้งข้อผิดพลาดแก่ผู้ขอ
  ไม่สร้างคำขอค้างไว้ และการส่งใหม่ต้องไม่ทำให้เกิดคำขอซ้ำซ้อนของรายการเดียวกัน
  ก่อนกด "ส่งคำขอยืม" ผู้ขอต้องกลับไปแก้ไขข้อมูลในฟอร์มได้โดยระบบยังไม่สร้างคำขอ
                                                                   <- UC-02 exception 10a, alternative 8a
- FR-BRQ-10 ระบบต้องรองรับการยืมแบบค้างคืนในฟีเจอร์นี้ โดยผู้ขอเลือกประเภทการยืม "ปกติ" หรือ "ค้างคืน"
  (ก) เลือก "ค้างคืน" ต้องระบุเหตุผลการยืมและแนบเอกสารประกอบ (ใบบันทึกข้อความ) จึงจะส่งคำขอได้ และเก็บไว้กับคำขอ
  (ข) เลือก "ปกติ" ระบบต้องแสดงเงื่อนไขการยืมปกติก่อนส่ง
      (คืนภายใน 16:00 น. ของวันเดียวกัน ใช้งานภายในพื้นที่มหาวิทยาลัย)
                                                                   <- RQ-16, UC-05, UC-02 main flow 5 และ 7, alternative 5a, DOM-LOAN-01

## Quality Requirements
NFR ของระบบอยู่ที่ docs/srs/SRS.md หัวข้อ 3.3 ฟีเจอร์นี้อ้าง ID เดิม ไม่สร้าง NFR ใหม่
- NFR-SEC-01 รับส่งผ่าน TLS 1.2 ขึ้นไป และต้องยืนยันตัวตนก่อนทุกครั้ง (ใช้กับทุก endpoint ของฟีเจอร์นี้)
- NFR-AVAIL-01 พร้อมใช้งานอย่างน้อย 99% ช่วง 08.30-16.30 น. วันจันทร์-ศุกร์
- NFR-USE-01 ใช้งานบนหน้าจอมือถือได้
- NFR-PERF-01 ปัจจุบันเขียนถึงเฉพาะหน้ารายการอุปกรณ์ (RQ-24) แต่ Use Case Spec UC-02 ระบุว่าแบบฟอร์มคำขอ
  ต้องแสดงผลภายใน 3 วินาทีด้วย ยังไม่นำมาใช้กับฟีเจอร์นี้จนกว่าจะตัดสิน (ดู Q-BRQ-05 ต้องทำ CR กับของกลาง)

## Acceptance Criteria
- [ ] AC-BRQ-01 (FR-BRQ-01)
      Given นักศึกษาเปิดแบบฟอร์มคำขอของอุปกรณ์ชิ้นที่สถานะ "ว่าง"
      When  อุปกรณ์ชิ้นนั้นถูกเปลี่ยนเป็น "ถูกยืม" ระหว่างกรอก แล้วนักศึกษากดส่งคำขอ
      Then  ระบบต้องไม่สร้างคำขอ และแจ้งสถานะล่าสุดของอุปกรณ์
- [ ] AC-BRQ-02 (FR-BRQ-02)
      Given นักศึกษาเปิดแบบฟอร์มคำขอของอุปกรณ์ที่ว่าง
      When  เลือกวัตถุประสงค์การยืม 1 ประเภท กรอกข้อมูลครบ แล้วส่งคำขอสำเร็จ
      Then  คำขอที่บันทึกต้องมีวัตถุประสงค์ที่เลือกไว้
- [ ] AC-BRQ-03 (FR-BRQ-03)
      Given ข้อมูลคำขอไม่ครบถ้วน (เช่น ไม่ได้ระบุช่วงเวลาที่ต้องการยืม)
      When  นักศึกษากดส่งคำขอ
      Then  ระบบต้องไม่สร้างคำขอ และระบุช่องข้อมูลที่ยังต้องกรอก
- [ ] AC-BRQ-04 (FR-BRQ-04)
      Given นักศึกษาไม่มีรายการคืนเกินกำหนดค้างอยู่ และอุปกรณ์ชิ้นนั้นสถานะ "ว่าง"
      When  กรอกข้อมูลครบถ้วนและกดส่งคำขอ
      Then  ระบบต้องสร้างคำขอด้วยสถานะ "รออนุมัติ" พร้อมผู้ขอ อุปกรณ์รายชิ้น ประเภทการยืม
            และเวลาที่ส่งตามเวลา Asia/Bangkok โดยสถานะของอุปกรณ์ยังเป็น "ว่าง"
- [ ] AC-BRQ-05 (FR-BRQ-05)
      Given อุปกรณ์ชิ้นหนึ่งมีคำขอค้างอยู่แล้ว 1 คำขอจากนักศึกษาคนอื่น
      When  นักศึกษาอีกคนส่งคำขอของอุปกรณ์ชิ้นเดียวกัน
      Then  ระบบต้องรับคำขอไว้ และแสดงว่ามีคำขอมาก่อน 1 รายการพร้อมเวลาที่ส่งของคำขอนั้น
            โดยไม่เปิดเผยชื่อผู้ขอรายอื่น (DOM-PRIV-01)
      หมายเหตุ: รูปแบบและหน้าที่แสดงยังรอ Q-SH-05
- [ ] AC-BRQ-06 (FR-BRQ-06)
      Given นักศึกษามีอุปกรณ์ที่คืนเกินกำหนดค้างอยู่ในระบบ
      When  พยายามส่งคำขอยืมใหม่
      Then  ระบบต้องปฏิเสธคำขอ แจ้งสาเหตุ และไม่สร้างคำขอ
- [ ] AC-BRQ-07 (FR-BRQ-07)
      Given นักศึกษาสังกัดภาควิชาที่ 2 และอุปกรณ์ชิ้นเป้าหมายเป็นของภาควิชาที่ 1
      When  ส่งคำขอยืมอุปกรณ์ชิ้นนั้น
      Then  ระบบต้องปฏิเสธ ไม่สร้างคำขอ และไม่ส่งข้อมูลอุปกรณ์กลับไป
- [ ] AC-BRQ-08 (FR-BRQ-08)
      Given มีผู้ขอที่ส่งคำขอสำเร็จ 1 ครั้ง และถูกปฏิเสธ 1 ครั้ง
      When  ตรวจ audit log
      Then  ต้องมีบันทึกครบทั้ง 2 ครั้ง ระบุผู้ขอ เวลา รหัสครุภัณฑ์ และผลลัพธ์ของแต่ละครั้ง
- [ ] AC-BRQ-09 (FR-BRQ-09)
      Given การบันทึกคำขอลงฐานข้อมูลไม่สำเร็จ
      When  นักศึกษากดส่งคำขอ แล้วกดส่งใหม่อีกครั้งจนสำเร็จ
      Then  ครั้งแรกต้องแจ้งข้อผิดพลาดและไม่มีคำขอค้างในระบบ และเมื่อสำเร็จต้องมีคำขอเพียง 1 รายการ
- [ ] AC-BRQ-10 (FR-BRQ-10)
      Given นักศึกษาเลือกประเภทการยืมเป็น "ค้างคืน"
      When  ยังไม่ระบุเหตุผล หรือยังไม่แนบเอกสารประกอบ แล้วกดส่งคำขอ
      Then  ระบบต้องไม่สร้างคำขอ และระบุสิ่งที่ยังขาด
      และ
      Given นักศึกษาเลือกประเภทการยืมเป็น "ปกติ"
      When  อยู่ในแบบฟอร์มคำขอก่อนกดส่ง
      Then  ระบบต้องแสดงเงื่อนไขว่าต้องคืนภายใน 16:00 น. ของวันเดียวกัน และใช้งานภายในพื้นที่มหาวิทยาลัย

## Assumptions & Open Questions
คำถามของฟีเจอร์นี้ใช้รหัส Q-BRQ-xx เพื่อไม่ให้ชนกับ Q-xx ของ 001 ส่วน Q-SH-xx คือคำถามของกลาง

- ASM-BRQ-01 ผู้ขอยืนยันตัวตนสำเร็จแล้ว และระบบรู้บทบาทกับภาควิชาของผู้ขอก่อนเข้าฟีเจอร์นี้ (IF-IDP-01, DM-08)
- ASM-BRQ-02 หน่วยที่ขอยืมคือ "อุปกรณ์รายชิ้น" ตาม FR-EQS-06 ฉบับปัจจุบัน
  ถ้า Q-16 ของ 001 ยืนยันว่านักศึกษาเลือกชิ้นเองไม่ได้ จะกลายเป็นการขอยืมระดับรุ่น ต้องทำ CR
  กระทบ FR-BRQ-01, FR-BRQ-04, FR-BRQ-05, FR-BRQ-08 และโครงตารางคำขอ
- ASM-BRQ-03 ข้อตกลงทางเทคนิคกับเจ้าของ 001 (ไม่ใช่ข้อกำหนดจากผู้ใช้ รายละเอียดอยู่ใน plan.md)
  ใช้เลข migration `0003_borrow_request.up.sql` ตามตารางเลข migration ใน specs/000-shared/data-model.md
  คอลัมน์ id ของ `borrow_request` เป็น SERIAL (INT) ให้ชนิดตรงกับ `audit_log.request_id` ที่เป็น INT
  และ 002 เป็นผู้เพิ่ม foreign key จาก `audit_log.request_id` มาที่ `borrow_request.id` ใน migration ของตนเอง
- ASM-BRQ-04 เอกสารประกอบการยืมค้างคืนเป็นไฟล์ที่ผู้ขออัปโหลดเข้าระบบ ไม่ใช่เอกสารกระดาษที่ส่งนอกระบบ
  (ตีความจาก RQ-16 "แนบเอกสารประกอบ" และ SRS 3.1 ที่ระบุว่ามีที่เก็บไฟล์) ต้องยืนยัน ดู Q-BRQ-06
- Q-BRQ-01 FR-BRQ-02 ค่าวัตถุประสงค์การยืมที่เลือกได้มีอะไรบ้าง RQ-18 เขียนแค่ "เช่น เพื่อการเรียน หรือเพื่อทำกิจกรรม"
  เลือกได้ค่าเดียวหรือหลายค่า และมีช่องพิมพ์เองไหม? -> ถามนักศึกษา / เจ้าหน้าที่
- Q-BRQ-02 FR-BRQ-03 ช่องใดบ้างถือว่า "ครบถ้วน" ตาม RQ-22 และ "ช่วงเวลาที่ต้องการยืม" กรอกเป็นอะไร
  (วันที่และเวลาเริ่ม-สิ้นสุด หรือเลือกจากคาบเรียน)? -> ถามนักศึกษา / เจ้าหน้าที่
- Q-BRQ-03 FR-BRQ-06 "มีอุปกรณ์ที่คืนเกินกำหนดค้างอยู่" นับจากอะไรและปลดเมื่อไร
  (คืนของแล้วปลดทันที หรือมีระยะเวลาลงโทษตาม RQ-27 ซึ่งยังไม่มีนิยาม ดู Q-SH-07)
  และ BL-23 เป็น Could อยู่ใน prototype ไหม? -> ถามเจ้าหน้าที่ / อาจารย์หัวหน้าโครงการ
- Q-BRQ-04 FR-BRQ-09 ผู้ขอส่งคำขอของ "ตนเอง" ซ้ำบนอุปกรณ์ชิ้นเดิมที่ยังรออนุมัติอยู่ ให้ปฏิเสธหรือยอมให้ซ้อนได้?
  UC-02 ระบุไว้เฉพาะคำขอของผู้อื่น (DOM-REQ-01) -> ถามนักคอมพิวเตอร์
- Q-BRQ-05 NFR-PERF-01 ครอบคลุมแบบฟอร์มคำขอของฟีเจอร์นี้ด้วยไหม UC-02 เขียนว่าใช่
  แต่ NFR-PERF-01 (RQ-24) เขียนถึงเฉพาะหน้ารายการอุปกรณ์ ถ้าใช่ต้องทำ CR กับของกลาง
  -> ทีม / นักเทคโนโลยีสารสนเทศ
- Q-BRQ-06 FR-BRQ-10 เอกสารประกอบการยืมค้างคืนรับไฟล์ชนิดใด ขนาดไม่เกินเท่าไร และเก็บที่ไหน
  RQ-16 เขียนแค่ "ใบบันทึกข้อความ" -> ถามเจ้าหน้าที่ / นักเทคโนโลยีสารสนเทศ
- Q-BRQ-07 FR-BRQ-08 ค่า `action` ของ audit_log สำหรับการส่งคำขอยืมยังไม่มีในตาราง DM-07
  (ตอนนี้มี list, search, detail ของ 001 และ cancel ของ 003) ใช้ชื่อค่าอะไร
  และต้องแยกค่าของยืมปกติกับค้างคืนไหม? -> จองค่าในกลุ่ม แล้วเพิ่มใน DM-07 พร้อม migration ของ 002
- Q-BRQ-08 FR-BRQ-04 ชื่อสถานะของคำขอหลังจาก "รออนุมัติ" ใช้คำว่าอะไรบ้าง
  (specs/000-shared/data-model.md ยังเป็นร่างจาก Infrastructure และระบุให้เจ้าของ 002 ยืนยัน)
  ขึ้นกับ 004 (อนุมัติ) และ 003 (ยกเลิก) ด้วย -> ทีม
- Q-16 [ของ 001 ดู specs/001-equipment-status/spec.md] นักศึกษาเลือกอุปกรณ์รายชิ้นเองได้ไหม
  ถ้าคำตอบคือไม่ได้ ต้องทำ CR กับ FR-EQS-06 และ FR-BRQ ตามที่เขียนไว้ใน ASM-BRQ-02
- Q-SH-04 [ของกลาง] กำหนดคืนของการยืมค้างคืนคือเมื่อไร (DOM-LOAN-01 ใช้กับยืมปกติเท่านั้น) กระทบ FR-BRQ-10
- Q-SH-05 [ของกลาง] ลำดับและเวลาของคำขอที่มาก่อนแสดงให้ใครเห็นและที่หน้าไหน กระทบ FR-BRQ-05, AC-BRQ-05
- Q-SH-06 [ของกลาง] เมื่อคำขอหนึ่งได้รับอนุมัติ คำขอที่เหลือของอุปกรณ์ชิ้นเดียวกันเป็นอย่างไร
  กระทบการอธิบายผลของคำขอที่ส่งซ้อน (FR-BRQ-05)
- Q-SH-08 [ของกลาง] ถ้าระบบยืนยันตัวตนของมหาวิทยาลัยเชื่อมต่อไม่ได้ ระบบต้องทำอย่างไร (กระทบ ASM-BRQ-01)
