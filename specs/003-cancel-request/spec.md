Spec ID: SPEC-CXL-003 | Source: RQ-03, RQ-25, คำตอบของเจ้าของฟีเจอร์ (2569-11-10) และ /clarify รอบที่ 1 | Use case: UC-15

Backlog: BL-20 (specs/backlog.md)

## Goal
นักศึกษายกเลิกคำขอยืมของตนเองได้ด้วยตนเองผ่านระบบ ตราบใดที่คำขอนั้นยังไม่ได้รับการอนุมัติ (RQ-03)
เพื่อให้คำขอที่นักศึกษาไม่ต้องการแล้วไม่ค้างรอการอนุมัติ และเจ้าหน้าที่ไม่ต้องพิจารณาคำขอที่ถูกยกเลิกไปแล้ว

## Scope
### In scope
- หน้า "คำขอที่รออนุมัติของฉัน" แสดงคำขอที่ยังรออนุมัติของนักศึกษาที่เข้าสู่ระบบ พร้อมปุ่มยกเลิก (ปิด Q-04)
- นักศึกษายกเลิกคำขอยืมของตนเองที่ยังไม่ได้รับการอนุมัติ โดยต้องยืนยันอีกครั้งก่อนยกเลิก (RQ-03, Q-04)
- ระบบไม่ยอมให้ยกเลิกคำขอที่ได้รับการอนุมัติ ถูกปฏิเสธ หรือถูกยกเลิกไปแล้ว
  รวมถึงกรณีที่เจ้าหน้าที่อนุมัติก่อนนักศึกษากดยืนยัน (RQ-03, Q-04)
- บันทึกประวัติการยกเลิก (RQ-25)
- นักศึกษาต้องระบุเหตุผลการยกเลิก (ปิด Q-05)
- แจ้งเจ้าหน้าที่ทาง Email เมื่อมีการยกเลิก (IF-NOT-01, ปิด Q-06)
### Out of scope
- ส่งคำขอยืม (UC-02 ของ 002) | ขอยืมแบบค้างคืน (UC-05) | อนุมัติ / ปฏิเสธคำขอ (UC-12 ของ 004, UC-14)
- ตรวจสอบสถานะคำขอยืมของตนเอง (UC-06, RQ-10): หน้า "คำขอที่รออนุมัติของฉัน" **ไม่ใช่ UC-06**
  ไม่แสดงคำขอสถานะอื่น และไม่แสดงประวัติคำขอ (Q-04)
- ยกเลิกการยืมหลังส่งมอบอุปกรณ์แล้ว (เป็นเรื่องของ UC-08 / UC-09)
- แก้ไขคำขอยืม (ไม่มี RQ รองรับ)
- ยืนยันตัวตน (ระบบยืนยันตัวตนของมหาวิทยาลัย IF-IDP-01) ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- เจ้าหน้าที่ยกเลิกคำขอแทนนักศึกษา (FR-CXL-10): อยู่ในข้อกำหนด แต่**ไม่ทำใน prototype** (ปิด Q-10)
  เพราะต้องมีหน้าใหม่ของฝั่งเจ้าหน้าที่ และไม่มี RQ รองรับ

## Constraints
ใช้ร่วม (ข้อความเต็มอยู่ที่ specs/000-shared/constraints.md ห้าม copy มาไว้ที่นี่):
- CON-TECH-01 ฐานข้อมูล PostgreSQL
- CON-TECH-02 HTTPS เท่านั้น deploy ด้วย Docker
- CON-DATA-01 สถานะอุปกรณ์ 3 ค่าเท่านั้น: ว่าง, ถูกยืม, ไม่พร้อมใช้งาน
- DOM-REQ-01 อุปกรณ์ที่มีคำขอค้างยังเป็น "ว่าง" ส่งคำขอชิ้นเดียวกันซ้อนได้
- IF-IDP-01 ต้องยืนยันตัวตนผ่านระบบยืนยันตัวตนของมหาวิทยาลัยก่อน
- IF-NOT-01 ส่งการแจ้งเตือนผ่านระบบแจ้งเตือน Email
เฉพาะฟีเจอร์นี้:
- CON-CXL-01 ฟีเจอร์นี้ไม่เปลี่ยนสถานะอุปกรณ์ เปลี่ยนเฉพาะสถานะของคำขอ
  ดูแถว UC-15 ในตาราง "ใครเปลี่ยนสถานะอุปกรณ์" ใน specs/000-shared/data-model.md
- CON-CXL-02 ชื่อสถานะของคำขอใช้ตาม workflow บน Miro ที่บันทึกใน data-model.md (DM-06) ดังตารางด้านล่าง (ปิด Q-01)
  ชื่อตรงกับ spec ของ 002 แล้ว (เจ้าของ 003 ยืนยัน 2569-11-10) ถ้า 002 เปลี่ยนชื่อภายหลัง ให้ยึด 002 แล้วแก้ spec นี้

  | สถานะของคำขอ | ความหมาย | ยกเลิกได้ (FR-CXL-01 / 02) |
  |---|---|---|
  | Requested | ส่งแล้ว รออนุมัติ | ได้ |
  | Approved by Officer | ค้างคืน: เจ้าหน้าที่ผ่านขั้นแรกแล้ว | ได้ (Q-02) |
  | Pending Advisor Approval | ค้างคืน: รออาจารย์หัวหน้าโครงการเซ็น | ได้ (Q-02) |
  | Approved | อนุมัติแล้ว | ไม่ได้ |
  | Rejected | ปฏิเสธ | ไม่ได้ |
  | Handed Over | ส่งมอบแล้ว | ไม่ได้ |
  | Returned | คืนแล้ว | ไม่ได้ |
  | ยกเลิก | ถูกยกเลิกแล้ว (UC-15) | ไม่ได้ |

  "ยังไม่ได้รับการอนุมัติ" / "รออนุมัติ" ใน spec นี้ = Requested, Approved by Officer, Pending Advisor Approval
  เส้นทาง (ปิด Q-12):
  - ยืมปกติ: Requested -> Approved -> Handed Over -> Returned (ไม่ผ่าน Approved by Officer)
  - ยืมค้างคืน: Requested -> Approved by Officer -> Pending Advisor Approval -> Approved -> Handed Over -> Returned
  - Rejected เกิดได้ 2 ขั้น: เจ้าหน้าที่ปฏิเสธ หรือหลังอาจารย์หัวหน้าโครงการไม่เซ็น (เจ้าหน้าที่บันทึกผลใน UC-14)
  - ยกเลิก เกิดได้จาก Requested, Approved by Officer, Pending Advisor Approval เท่านั้น

## Requirements
- FR-CXL-01 ระบบต้องอนุญาตให้นักศึกษายกเลิกคำขอยืมของตนเองได้ เมื่อคำขอนั้นยังไม่ได้รับการอนุมัติ
  เมื่อยกเลิกสำเร็จ สถานะของคำขอต้องเปลี่ยนเป็น "ยกเลิก" และระบบต้องแจ้งนักศึกษาว่า
  "ยกเลิกคำขอยืม {ชื่อรุ่น} ({รหัสครุภัณฑ์}) เรียบร้อยแล้ว" (ASM-13)
  คำขอยืมแบบค้างคืนที่เจ้าหน้าที่ผ่านขั้นแรกแล้ว แต่ยังไม่มีผลอนุมัติของอาจารย์หัวหน้าโครงการ ยังยกเลิกได้ (ปิด Q-02)
  สถานะของคำขอที่ยกเลิกได้: Requested, Approved by Officer, Pending Advisor Approval (CON-CXL-02)
  ถ้าบันทึกการยกเลิกไม่สำเร็จ (เช่น ฐานข้อมูลไม่ตอบสนอง) ระบบต้องแจ้งข้อผิดพลาด สถานะของคำขอต้องคงเดิม
  และนักศึกษาต้องลองยกเลิกใหม่ได้ (ASM-06)                                       <- RQ-03, UC-15, Q-01, Q-02, Q-08
- FR-CXL-02 เมื่อคำขออยู่ในสถานะ Approved, Rejected, Handed Over, Returned หรือ ยกเลิก (CON-CXL-02)
  ระบบต้องไม่ยกเลิกคำขอนั้น และสถานะของคำขอต้องคงเดิม
  กรณี Approved ระบบต้องแจ้งนักศึกษาว่ายกเลิกไม่ได้เพราะคำขอได้รับการอนุมัติแล้ว
  กรณี Rejected, Handed Over, Returned และ ยกเลิก ระบบต้องแจ้งว่า "คำขอนี้ยกเลิกไม่ได้"     <- RQ-03, Q-01, Q-03, Q-04
- FR-CXL-03 นักศึกษายกเลิกได้เฉพาะคำขอยืมของตนเอง ถ้าพยายามยกเลิกคำขอของผู้อื่น
  ระบบต้องปฏิเสธโดยแจ้งว่า "ไม่พบคำขอ" (ไม่บอกว่ามีคำขอนั้นอยู่) และสถานะของคำขอนั้นต้องคงเดิม
  ผู้ใช้บทบาทเจ้าหน้าที่ที่เรียกหน้า "คำขอที่รออนุมัติของฉัน" หรือสั่งยกเลิก ต้องถูกปฏิเสธ (403) เพราะ FR-CXL-10 ไม่ทำใน prototype (ASM-13)
                                                                                    <- RQ-03 (ตีความ ASM-03), Q-03, Q-04
- FR-CXL-04 ระบบต้องตัดสินว่ายกเลิกได้หรือไม่จากสถานะของคำขอ ณ เวลาที่นักศึกษากดยืนยันการยกเลิก
  ไม่ใช่สถานะที่นักศึกษาเห็นบนหน้าจอ ถ้าเจ้าหน้าที่อนุมัติไปก่อนแล้ว ให้ทำตาม FR-CXL-02  <- RQ-03, Q-04
- FR-CXL-05 ระบบต้องบันทึกประวัติลง audit_log (DM-07) ทุกครั้งที่นักศึกษาที่ยืนยันตัวตนแล้วพยายามยกเลิกคำขอ
  รวมกรณีพยายามยกเลิกคำขอของผู้อื่น: ผู้ยกเลิก เวลา คำขอที่ยกเลิก (`request_id`) และผลลัพธ์ (สำเร็จ = `ok` / ไม่สำเร็จ = `forbidden`)
  ตามตารางด้านล่าง (ASM-12) คำสั่งยกเลิกที่ยังไม่ได้ยืนยันตัวตน (AC-CXL-07) ไม่ต้องบันทึก (ASM-07)  <- RQ-25, Q-07, Q-13
  | กรณี | action | outcome | request_id | query (สาเหตุ) |
  |---|---|---|---|---|
  | ยกเลิกสำเร็จ | `cancel` | `ok` | รหัสคำขอ | `{"reason_len": n}` |
  | คำขอของผู้อื่น | `cancel` | `forbidden` | รหัสคำขอ | `{"cause":"not_owner"}` |
  | ไม่มีคำขอนี้ | `cancel` | `forbidden` | ว่าง | `{"cause":"not_found","id":…}` |
  | อนุมัติแล้ว | `cancel` | `forbidden` | รหัสคำขอ | `{"cause":"already_approved"}` |
  | Rejected / Handed Over / Returned / ยกเลิก | `cancel` | `forbidden` | รหัสคำขอ | `{"cause":"not_cancellable"}` |
  | เหตุผลว่างหรือเกิน 200 ตัวอักษร | `cancel` | `forbidden` | รหัสคำขอ | `{"cause":"reason_invalid"}` |
  | ส่ง Email ไม่สำเร็จ (FR-CXL-09) | `notify` | `error` | รหัสคำขอ | `{"for":"cancel"}` |
  | ยังไม่ได้ยืนยันตัวตน | ไม่บันทึก (ASM-07) | | | |
- FR-CXL-06 ระบบต้องมีหน้า "คำขอที่รออนุมัติของฉัน" ที่แสดงเฉพาะคำขอยืมของนักศึกษาที่เข้าสู่ระบบ
  และมีสถานะ Requested, Approved by Officer หรือ Pending Advisor Approval (CON-CXL-02)
  ไม่แสดงคำขอสถานะอื่น และไม่แสดงประวัติคำขอ
  แต่ละรายการแสดงชื่อรุ่นและรหัสครุภัณฑ์ของอุปกรณ์ที่ขอ เวลาที่ส่งคำขอ (DM-06) และปุ่มยกเลิก
  เรียงจากคำขอที่ส่งล่าสุดอยู่บนสุด ถ้าเวลาที่ส่งเท่ากัน เรียงตามรหัสคำขอจากมากไปน้อย (ASM-13)
  ถ้าไม่มีคำขอที่รออนุมัติ แสดงข้อความ "ไม่มีคำขอที่รออนุมัติ"
  ถ้าโหลดรายการไม่สำเร็จ แสดงข้อความ "โหลดรายการไม่สำเร็จ กรุณาลองใหม่อีกครั้ง" พร้อมปุ่ม "ลองใหม่" และต้องไม่แสดงข้อความว่าไม่มีคำขอ (ASM-13)
                                                                                    <- Q-04, Q-11
- FR-CXL-07 เมื่อนักศึกษากดปุ่มยกเลิก ระบบต้องให้ยืนยันอีกครั้งพร้อมระบุเหตุผล (FR-CXL-08) ก่อนยกเลิก
  ถ้ายืนยัน ให้ยกเลิกตาม FR-CXL-01 แล้วรายการนั้นต้องหายจากหน้า "คำขอที่รออนุมัติของฉัน"
  ถ้าไม่ยืนยัน สถานะของคำขอต้องคงเดิม รายการยังอยู่ในหน้า และเมื่อเปิดกล่องยืนยันใหม่ ช่องเหตุผลต้องว่าง (ASM-13)
                                                                                    <- Q-04, Q-05
- FR-CXL-08 นักศึกษาต้องพิมพ์เหตุผลการยกเลิกก่อนยืนยัน ถ้าช่องเหตุผลว่าง (หรือมีแต่ช่องว่าง) ระบบต้องไม่ยอมให้ยืนยัน
  และสถานะของคำขอต้องคงเดิม เหตุผลต้องยาวไม่เกิน 200 ตัวอักษร ถ้าเกินระบบต้องไม่ยอมให้ยืนยัน
  "ตัวอักษร" นับตาม code point (เช่น "ที่" = 3) ทั้งหน้าจอและหลังบ้านนับแบบเดียวกัน
  และหน้าจอแสดงตัวนับ "x/200" ใต้ช่องเหตุผล (ASM-13)
  เมื่อยกเลิกสำเร็จ ระบบต้องเก็บเหตุผลไว้กับคำขอนั้น                                 <- Q-05, Q-14
- FR-CXL-09 เมื่อยกเลิกสำเร็จ ระบบต้องส่ง Email ผ่าน IF-NOT-01 ถึงเจ้าหน้าที่ของภาควิชาที่เป็นเจ้าของอุปกรณ์ที่ขอ
  ระบุผู้ยกเลิก ชื่อรุ่นและรหัสครุภัณฑ์ เวลาที่ยกเลิก และเหตุผล (ASM-08)
  ถ้าส่ง Email ไม่สำเร็จ การยกเลิกยังถือว่าสำเร็จ สถานะของคำขอยังเป็น "ยกเลิก" และระบบต้องบันทึกว่าส่งแจ้งเตือนไม่สำเร็จใน audit_log
  (action `notify` outcome `error` ตามตารางใน FR-CXL-05)
  (แหล่งรายชื่อ Email ของเจ้าหน้าที่ รอ Q-15)                                     <- Q-06
- FR-CXL-10 [ไม่ทำใน prototype] เจ้าหน้าที่ยกเลิกคำขอแทนนักศึกษาได้ เมื่อคำขออยู่ในสถานะที่ยกเลิกได้ (CON-CXL-02)
  รายละเอียด (หน้าจอของเจ้าหน้าที่ ต้องระบุเหตุผลไหม แจ้งนักศึกษาไหม ยกเลิกได้เฉพาะภาควิชาตนเองไหม) รอ Q-16
  ยังไม่มี AC จนกว่าจะนำเข้า scope                                                 <- Q-10 (ไม่มี RQ รองรับ ทีมตัดสิน)
