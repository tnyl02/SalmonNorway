# Feature: ยกเลิกคำขอยืม (Cancel Borrow Request)
Spec ID: SPEC-CXL-003 | Source: RQ-03, คำตอบของเจ้าของฟีเจอร์ Q-01, Q-02 และ Q-04 (2569-11-10) | Use case: UC-15
Owner: 660710763 นางสาวนภัสนัน ดีเสมอ (@napatsanan-np) | Status: Draft v2 | Updated: 2569-11-10 (ปิด Q-01, Q-02, Q-04, Q-12)
Backlog: BL-20 (specs/backlog.md)

## Goal
นักศึกษายกเลิกคำขอยืมของตนเองได้ด้วยตนเองผ่านระบบ ตราบใดที่คำขอนั้นยังไม่ได้รับการอนุมัติ (RQ-03)
เพื่อให้คำขอที่นักศึกษาไม่ต้องการแล้วไม่ค้างรอการอนุมัติ และเจ้าหน้าที่ไม่ต้องพิจารณาคำขอที่ถูกยกเลิกไปแล้ว

## Scope
### In scope
- หน้า "คำขอที่รออนุมัติของฉัน" แสดงคำขอที่ยังรออนุมัติของนักศึกษาที่เข้าสู่ระบบ พร้อมปุ่มยกเลิก (ปิด Q-04)
- นักศึกษายกเลิกคำขอยืมของตนเองที่ยังไม่ได้รับการอนุมัติ โดยต้องยืนยันอีกครั้งก่อนยกเลิก (RQ-03, Q-04)
- ระบบไม่ยอมให้ยกเลิกคำขอที่ได้รับการอนุมัติ ถูกปฏิเสธ หรือถูกยกเลิกไปแล้ว
  รวมถึงกรณีที่เจ้าหน้าที่อนุมัติก่อนนักศึกษากดยืนยัน (RQ-03, Q-04)
- บันทึกประวัติการยกเลิก (RQ-25)
### Out of scope
- ส่งคำขอยืม (UC-02 ของ 002) | ขอยืมแบบค้างคืน (UC-05) | อนุมัติ / ปฏิเสธคำขอ (UC-12 ของ 004, UC-14)
- ตรวจสอบสถานะคำขอยืมของตนเอง (UC-06, RQ-10): หน้า "คำขอที่รออนุมัติของฉัน" **ไม่ใช่ UC-06**
  ไม่แสดงคำขอสถานะอื่น และไม่แสดงประวัติคำขอ (Q-04)
- ยกเลิกการยืมหลังส่งมอบอุปกรณ์แล้ว (เป็นเรื่องของ UC-08 / UC-09)
- แก้ไขคำขอยืม (ไม่มี RQ รองรับ)
- ยืนยันตัวตน (ระบบยืนยันตัวตนของมหาวิทยาลัย IF-IDP-01) ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- แจ้งเตือนเมื่อมีการยกเลิก (IF-NOT-01) ไม่มีใน RQ-03 ดู Q-06

## Constraints
ใช้ร่วม (ข้อความเต็มอยู่ที่ specs/000-shared/constraints.md ห้าม copy มาไว้ที่นี่):
- CON-TECH-01 ฐานข้อมูล PostgreSQL
- CON-TECH-02 HTTPS เท่านั้น deploy ด้วย Docker
- CON-DATA-01 สถานะอุปกรณ์ 3 ค่าเท่านั้น: ว่าง, ถูกยืม, ไม่พร้อมใช้งาน
- DOM-REQ-01 อุปกรณ์ที่มีคำขอค้างยังเป็น "ว่าง" ส่งคำขอชิ้นเดียวกันซ้อนได้
- IF-IDP-01 ต้องยืนยันตัวตนผ่านระบบยืนยันตัวตนของมหาวิทยาลัยก่อน
เฉพาะฟีเจอร์นี้:
- CON-CXL-01 ฟีเจอร์นี้ไม่เปลี่ยนสถานะอุปกรณ์ เปลี่ยนเฉพาะสถานะของคำขอ
  ดูแถว UC-15 ในตาราง "ใครเปลี่ยนสถานะอุปกรณ์" ใน specs/000-shared/data-model.md
- CON-CXL-02 ชื่อสถานะของคำขอใช้ตาม workflow บน Miro ที่บันทึกใน data-model.md (DM-06) ดังตารางด้านล่าง (ปิด Q-01)
  ชื่อตรงกับ spec ของ 002 แล้ว (เจ้าของ 003 ยืนยัน 2569-11-10) ถ้า 002 เปลี่ยนชื่อภายหลัง ให้ยึด 002 แล้วแก้ spec นี้

  | สถานะของคำขอ | ความหมาย | ยกเลิกได้ (FR-CXL-01 / 02) |
  |---|---|---|
  | Requested | ส่งแล้ว รออนุมัติ | ได้ |
  | Approved by Officer | ค้างคืน: เจ้าหน้าที่ผ่านขั้นแรกแล้ว | ได้ (Q-02) |
  | Pending Advisor Approval | ค้างคืน: รออาจารย์หัวหน้าโครงการเซ็น | ได้ (Q-02) |
  | Approved | อนุมัติแล้ว | ไม่ได้ |
  | Rejected | ปฏิเสธ | ไม่ได้ |
  | Handed Over | ส่งมอบแล้ว | ไม่ได้ |
  | Returned | คืนแล้ว | ไม่ได้ |
  | ยกเลิก | ถูกยกเลิกแล้ว (UC-15) | ไม่ได้ |

  "ยังไม่ได้รับการอนุมัติ" / "รออนุมัติ" ใน spec นี้ = Requested, Approved by Officer, Pending Advisor Approval
  เส้นทาง (ปิด Q-12):
  - ยืมปกติ: Requested -> Approved -> Handed Over -> Returned (ไม่ผ่าน Approved by Officer)
  - ยืมค้างคืน: Requested -> Approved by Officer -> Pending Advisor Approval -> Approved -> Handed Over -> Returned
  - Rejected เกิดได้ 2 ขั้น: เจ้าหน้าที่ปฏิเสธ หรือหลังอาจารย์หัวหน้าโครงการไม่เซ็น (เจ้าหน้าที่บันทึกผลใน UC-14)
  - ยกเลิก เกิดได้จาก Requested, Approved by Officer, Pending Advisor Approval เท่านั้น

## Requirements
- FR-CXL-01 ระบบต้องอนุญาตให้นักศึกษายกเลิกคำขอยืมของตนเองได้ เมื่อคำขอนั้นยังไม่ได้รับการอนุมัติ
  เมื่อยกเลิกสำเร็จ สถานะของคำขอต้องเปลี่ยนเป็น "ยกเลิก" และระบบต้องแจ้งนักศึกษาว่ายกเลิกสำเร็จ
  คำขอยืมแบบค้างคืนที่เจ้าหน้าที่ผ่านขั้นแรกแล้ว แต่ยังไม่มีผลอนุมัติของอาจารย์หัวหน้าโครงการ ยังยกเลิกได้ (ปิด Q-02)
  สถานะของคำขอที่ยกเลิกได้: Requested, Approved by Officer, Pending Advisor Approval (CON-CXL-02)  <- RQ-03, UC-15, Q-01, Q-02
- FR-CXL-02 เมื่อคำขออยู่ในสถานะ Approved, Rejected, Handed Over, Returned หรือ ยกเลิก (CON-CXL-02)
  ระบบต้องไม่ยกเลิกคำขอนั้น และสถานะของคำขอต้องคงเดิม
  กรณี Approved ระบบต้องแจ้งนักศึกษาว่ายกเลิกไม่ได้เพราะคำขอได้รับการอนุมัติแล้ว
  (ข้อความที่แจ้งกรณีสถานะอื่น รอ Q-03)                                          <- RQ-03, Q-01, Q-04
- FR-CXL-03 นักศึกษายกเลิกได้เฉพาะคำขอยืมของตนเอง ถ้าพยายามยกเลิกคำขอของผู้อื่น
  ระบบต้องปฏิเสธ และสถานะของคำขอนั้นต้องคงเดิม                                  <- RQ-03 (ตีความ ASM-03), Q-04
- FR-CXL-04 ระบบต้องตัดสินว่ายกเลิกได้หรือไม่จากสถานะของคำขอ ณ เวลาที่นักศึกษากดยืนยันการยกเลิก
  ไม่ใช่สถานะที่นักศึกษาเห็นบนหน้าจอ ถ้าเจ้าหน้าที่อนุมัติไปก่อนแล้ว ให้ทำตาม FR-CXL-02  <- RQ-03, Q-04
- FR-CXL-05 ระบบต้องบันทึกประวัติทุกครั้งที่มีการพยายามยกเลิกคำขอ: ผู้ยกเลิก เวลา คำขอที่ยกเลิก และผลลัพธ์ (สำเร็จ / ไม่สำเร็จ)
  ที่เก็บ (audit_log DM-07 หรือที่อื่น) รอ Q-07                                    <- RQ-25
- FR-CXL-06 ระบบต้องมีหน้า "คำขอที่รออนุมัติของฉัน" ที่แสดงเฉพาะคำขอยืมของนักศึกษาที่เข้าสู่ระบบ
  และมีสถานะ Requested, Approved by Officer หรือ Pending Advisor Approval (CON-CXL-02)
  ไม่แสดงคำขอสถานะอื่น และไม่แสดงประวัติคำขอ
  แต่ละรายการแสดงอุปกรณ์ที่ขอ เวลาที่ส่งคำขอ (DM-06) และปุ่มยกเลิก
  (ข้อมูลอุปกรณ์ที่แสดง การเรียงลำดับ และกรณีไม่มีคำขอ รอ Q-11)                  <- Q-04
- FR-CXL-07 เมื่อนักศึกษากดปุ่มยกเลิก ระบบต้องให้ยืนยันอีกครั้งก่อนยกเลิก
  ถ้ายืนยัน ให้ยกเลิกตาม FR-CXL-01 แล้วรายการนั้นต้องหายจากหน้า "คำขอที่รออนุมัติของฉัน"
  ถ้าไม่ยืนยัน สถานะของคำขอต้องคงเดิมและรายการยังอยู่ในหน้า                        <- Q-04 (ปิด Q-05 บางส่วน)

## Acceptance Criteria
- [ ] AC-CXL-01 (FR-CXL-01, CON-CXL-01, CON-DATA-01)
      Given นักศึกษา A ยืนยันตัวตนแล้ว และมีคำขอยืมแบบปกติที่ยังไม่ได้รับการอนุมัติ สำหรับอุปกรณ์รายชิ้น X ที่มีสถานะ "ว่าง"
      When  นักศึกษา A ยกเลิกคำขอนั้นและยืนยัน
      Then  สถานะของคำขอเป็น "ยกเลิก" นักศึกษา A ได้รับข้อความว่ายกเลิกสำเร็จ และอุปกรณ์รายชิ้น X ยังมีสถานะ "ว่าง"
- [ ] AC-CXL-02 (FR-CXL-02)
      Given นักศึกษา A มีคำขอยืมที่เจ้าหน้าที่อนุมัติแล้ว
      When  นักศึกษา A ส่งคำสั่งยกเลิกคำขอนั้นโดยตรง
      Then  ระบบแจ้งว่ายกเลิกไม่ได้เพราะคำขอได้รับการอนุมัติแล้ว และสถานะของคำขอยังเป็นอนุมัติแล้ว
- [ ] AC-CXL-03 (FR-CXL-03)
      Given นักศึกษา B มีคำขอยืมที่ยังไม่ได้รับการอนุมัติ
      When  นักศึกษา A ส่งคำสั่งยกเลิกคำขอของนักศึกษา B โดยตรง
      Then  ระบบปฏิเสธ และสถานะของคำขอของนักศึกษา B ไม่เปลี่ยน
- [ ] AC-CXL-04 (FR-CXL-04, FR-CXL-02, FR-CXL-07)
      Given นักศึกษา A เปิดหน้า "คำขอที่รออนุมัติของฉัน" และกดปุ่มยกเลิกคำขอหนึ่ง ระบบแสดงให้ยืนยัน
            แล้วเจ้าหน้าที่อนุมัติคำขอนั้นก่อนที่นักศึกษา A จะกดยืนยัน
      When  นักศึกษา A กดยืนยัน
      Then  ระบบไม่ยกเลิก แจ้งว่าคำขอได้รับการอนุมัติแล้ว และสถานะของคำขอยังเป็นอนุมัติแล้ว
- [ ] AC-CXL-05 (DOM-REQ-01, FR-CXL-01)
      Given อุปกรณ์รายชิ้น X มีคำขอที่ยังไม่ได้รับการอนุมัติ 2 คำขอ จากนักศึกษา A และนักศึกษา B
      When  นักศึกษา A ยกเลิกคำขอของตนเองและยืนยัน
      Then  คำขอของนักศึกษา A เป็น "ยกเลิก" ส่วนคำขอของนักศึกษา B ไม่เปลี่ยน และอุปกรณ์รายชิ้น X ยังเป็น "ว่าง"
- [ ] AC-CXL-06 (FR-CXL-05)
      Given นักศึกษา A ยกเลิกคำขอ 1 ครั้งสำเร็จ และพยายามยกเลิกคำขอที่อนุมัติแล้ว 1 ครั้ง
      When  ตรวจประวัติการยกเลิก
      Then  มีบันทึก 2 รายการ ระบุผู้ยกเลิก เวลา คำขอ และผลลัพธ์ (สำเร็จ 1 รายการ ไม่สำเร็จ 1 รายการ)
- [ ] AC-CXL-07 (IF-IDP-01, NFR-SEC-01)
      Given session ของนักศึกษา A หมดอายุ
      When  นักศึกษา A ส่งคำสั่งยกเลิกคำขอ
      Then  ระบบไม่ยกเลิก และส่งกลับหน้าเข้าสู่ระบบพร้อมข้อความแจ้ง
- [ ] AC-CXL-08 (FR-CXL-06, FR-CXL-03)
      Given นักศึกษา A มีคำขอที่รออนุมัติ 2 คำขอ คำขอที่อนุมัติแล้ว 1 คำขอ ถูกปฏิเสธ 1 คำขอ และยกเลิกแล้ว 1 คำขอ
            และนักศึกษา B มีคำขอที่รออนุมัติ 1 คำขอ
      When  นักศึกษา A เปิดหน้า "คำขอที่รออนุมัติของฉัน"
      Then  เห็นเฉพาะคำขอที่รออนุมัติของนักศึกษา A 2 รายการ แต่ละรายการแสดงอุปกรณ์ที่ขอ เวลาที่ส่งคำขอ และปุ่มยกเลิก
            ไม่เห็นคำขอสถานะอื่นของนักศึกษา A และไม่เห็นคำขอของนักศึกษา B
- [ ] AC-CXL-09 (FR-CXL-07)
      Given นักศึกษา A อยู่ในหน้า "คำขอที่รออนุมัติของฉัน" และมีคำขอที่รออนุมัติ 1 รายการ
      When  กดปุ่มยกเลิก แล้วเลือกไม่ยืนยัน จากนั้นกดปุ่มยกเลิกอีกครั้งแล้วยืนยัน
      Then  ครั้งแรกสถานะของคำขอไม่เปลี่ยนและรายการยังอยู่ ครั้งที่สองสถานะของคำขอเป็น "ยกเลิก" และรายการหายจากหน้า
- [ ] AC-CXL-10 (FR-CXL-01, Q-02)
      Given นักศึกษา A มีคำขอยืมแบบค้างคืนที่เจ้าหน้าที่ผ่านขั้นแรกแล้ว แต่ยังไม่มีผลอนุมัติของอาจารย์หัวหน้าโครงการ
      When  นักศึกษา A ยกเลิกคำขอนั้นและยืนยัน
      Then  สถานะของคำขอเป็น "ยกเลิก"
- [ ] AC-CXL-11 (FR-CXL-02)
      Given นักศึกษา A มีคำขอที่ถูกปฏิเสธแล้ว 1 คำขอ และคำขอที่ยกเลิกไปแล้ว 1 คำขอ
      When  นักศึกษา A ส่งคำสั่งยกเลิกแต่ละคำขอโดยตรง
      Then  ระบบไม่ยกเลิก และสถานะของทั้ง 2 คำขอคงเดิม
