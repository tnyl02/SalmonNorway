## Goal
เจ้าหน้าที่ตรวจสอบและอนุมัติหรือปฏิเสธคำขอยืมแบบปกติได้ในระบบก่อนส่งมอบอุปกรณ์ทุกครั้ง ตามลำดับเวลาที่ส่ง
และบันทึกผลคำขอยืมแบบค้างคืนตามเอกสารที่อาจารย์เซ็นแล้ว (UC-14, RQ-15, CR-009)
ผู้ขอได้รับแจ้งผลทาง Email ภายใน 60 วินาทีหลังมีการดำเนินการ (RQ-14, RQ-21)

## Scope
### In scope
- หน้ารายการคำขอของเจ้าหน้าที่ แสดงคำขอยืมแบบปกติสถานะ `requested` ของภาควิชาตนเอง แล้วอนุมัติหรือปฏิเสธ (UC-12, RQ-14)
- อนุมัติหรือปฏิเสธคำขอยืมแบบค้างคืนสถานะ `requested` ของภาควิชาตนเอง กดครั้งเดียวพร้อมชื่ออาจารย์ที่เซ็น 1 คำขอ = 1 ชิ้น (UC-14, RQ-15, CR-009 ทาง ก)
- ปฏิเสธคำขออื่นของอุปกรณ์รายชิ้นเดียวกันโดยอัตโนมัติเมื่อมีคำขอหนึ่งได้รับอนุมัติ ทั้งยืมปกติและค้างคืน (Q-SH-06, Q-APV-14)
- ปฏิเสธอัตโนมัติคำขอยืมแบบปกติที่ไม่มีใครพิจารณาเมื่อถึงเที่ยงคืนของวันที่ส่ง (ASM-05, Q-APV-14, Q-APV-15)
- แจ้งผลให้ผู้ขอทาง Email ส่งซ้ำเมื่อไม่สำเร็จ และรายการ "Email ที่ส่งไม่สำเร็จ" ให้เจ้าหน้าที่กดส่งซ้ำ (RQ-21, IF-NOT-01)
- บันทึกประวัติการพิจารณาทุกครั้ง (RQ-25)
- เปลี่ยนสถานะของคำขอเท่านั้น สถานะอุปกรณ์ยังเป็น "ว่าง" จนกว่า 005 ส่งมอบ (data-model.md แถว UC-12, DOM-REQ-01)
### Out of scope
- ส่งคำขอยืม UC-02 / UC-05 (002) และยกเลิกคำขอ UC-15 (003)
- หน้าตรวจเอกสารขออนุมัติค้างคืนแยก (UC-11, BL-17) และคำขอค้างคืนหลายชิ้นใน 1 คำขอ (CR-009 ทาง ข และ ค ไม่เลือก)
- บันทึกการส่งมอบและกำหนดคืน UC-08 (005)
- นักศึกษาตรวจสอบสถานะคำขอของตนเอง UC-06 (RQ-10, BL-15)
- แสดงลำดับคำขอที่หน้ารายละเอียดอุปกรณ์ (001 ตาม Q-SH-05)
- จองอุปกรณ์ล่วงหน้า (BL-11, Won't ตาม N-01)
- แจ้งเตือนก่อนถึงกำหนดคืน (RQ-12)
- เปลี่ยนผลการพิจารณาที่บันทึกแล้ว

## Constraints

- CON-TECH-02 HTTPS เท่านั้น deploy ด้วย Docker
- CON-TECH-03 รูปแบบ error `{code, message}` และรหัสจากรายการกลาง (004 ลงทะเบียน `FORBIDDEN_ROLE`)
- CON-DATA-01 สถานะอุปกรณ์ 3 ค่าเท่านั้น (อนุมัติแล้วสถานะอุปกรณ์ไม่เปลี่ยน)
- DOM-REQ-01 คำขอค้างของอุปกรณ์ชิ้นเดียวกันส่งซ้อนได้ คำขอที่ได้รับอนุมัติก่อนได้อุปกรณ์

- IF-IDP-01 ต้องยืนยันตัวตนผ่านระบบของมหาวิทยาลัยก่อน และได้บทบาทกับภาควิชาของผู้ใช้กลับมา
- IF-NOT-01 แจ้งผู้ใช้ผ่านระบบแจ้งเตือน Email

## Requirements
ID ตรงกับ docs/srs/SRS.md หัวข้อ 3.1.4 (SRS ยังเป็น `[เติม]` ต้องเติมตาม spec นี้)

- FR-APV-01 ระบบต้องให้เจ้าหน้าที่ตรวจสอบและอนุมัติหรือปฏิเสธคำขอยืมแบบปกติ ก่อนส่งมอบอุปกรณ์ทุกครั้ง     <- RQ-14, US-007, UC-12
  (ก) หน้ารายการ: แสดงทุกคำขอยืมแบบปกติสถานะ `requested` ของอุปกรณ์ภาควิชาเดียวกับเจ้าหน้าที่ (IF-IDP-01)
      เรียงตามเวลาที่ส่งจากเก่าไปใหม่ แต่ละคำขอแสดงชื่อผู้ขอ อุปกรณ์ วัตถุประสงค์ และช่วงเวลาที่ต้องการยืม (ASM-06)
      เวลาที่ส่งเท่ากันเรียงตามรหัสคำขอจากน้อยไปมาก (Q-APV-30) / ไม่มีคำขอเลยแสดง "ไม่มีคำขอที่รออนุมัติ" (Q-APV-31)
  (ข) ลำดับ: อนุมัติได้เฉพาะคำขอแรก (ส่งก่อนสุด) ที่ยังเป็น `requested` ของอุปกรณ์รายชิ้นนั้น ข้ามลำดับไม่ได้
      ถ้าคำขอแรกไม่ผ่าน เจ้าหน้าที่ปฏิเสธพร้อมเหตุผล แล้วคำขอถัดไปกลายเป็นคำขอแรก (ASM-04, DOM-REQ-01)
      คำขอแรกที่เลย 16:00 น. ของวันที่เริ่มยืมแล้ว (อนุมัติไม่ได้ตาม ค) ยังนับเป็นคำขอแรก ระบบไม่ปฏิเสธเองและไม่ข้าม
      เจ้าหน้าที่ต้องปฏิเสธเองพร้อมเหตุผล หรือรอเที่ยงคืนตาม (ฉ) (Q-APV-16)
      ลำดับคำขอแรกนับเฉพาะคำขอยืมแบบปกติ คำขอค้างคืนไม่ขวางคิว (Q-APV-23)
      ลำดับคำขอแรกจำกัดเฉพาะการอนุมัติ เจ้าหน้าที่ปฏิเสธคำขอใดก็ได้ที่ยังเป็น `requested` (Q-APV-27)
  (ค) อนุมัติได้เมื่อคำขอเป็น `requested` และอุปกรณ์รายชิ้นมีสถานะ "ว่าง" เท่านั้น อนุมัติแล้วคำขอเป็น `approved`
      สถานะอุปกรณ์ยังเป็น "ว่าง" (data-model.md แถว UC-12) อนุมัติไม่ได้เมื่อเลย 16:00 น. ของวันที่เริ่มยืม (Q-APV-11, DOM-LOAN-01)
      "เลย 16:00 น." นับตั้งแต่ 16:00:00 น. ตรง คืออนุมัติได้ถึง 15:59:59 น. เท่านั้น (Q-APV-26)
  (ง) ปฏิเสธ: เจ้าหน้าที่ต้องระบุเหตุผล ปฏิเสธแล้วคำขอเป็น `rejected`
      เหตุผลยาวไม่เกิน 500 ตัวอักษร นับตาม code point แบบเดียวกับ 003 (Q-APV-28)
      ตรวจเหตุผลก่อนดูสถานะคำขอ เช่น คำขอที่ยกเลิกแล้วและไม่ระบุเหตุผลได้ "กรุณาระบุเหตุผลในการปฏิเสธ" (Q-APV-29)
      แต่ตรวจภาควิชาก่อนเหตุผล อุปกรณ์ภาควิชาอื่นได้ `FORBIDDEN_DEPARTMENT` เสมอ (Q-APV-34)
  (จ) เมื่อคำขอหนึ่งได้รับอนุมัติ คำขออื่นที่ยังเป็น `requested` ของอุปกรณ์รายชิ้นเดียวกันเป็น `rejected` ทันที (Q-SH-06)
      **ทั้งคำขอยืมแบบปกติและแบบค้างคืน** (Q-APV-14)
      เหตุผล "อุปกรณ์ชิ้นนี้ได้รับการอนุมัติให้คำขออื่นแล้ว" ผู้ดำเนินการคือเจ้าหน้าที่ที่กดอนุมัติ และส่ง Email ผลปฏิเสธ
  (ฉ) คำขอ**ยืมแบบปกติ**ที่ยังเป็น `requested` เมื่อถึงเที่ยงคืนของวันที่ส่ง (00:00 น. Asia/Bangkok) เป็น `rejected` ผู้ดำเนินการคือ System
      เหตุผล "คำขอยังคงค้างอยู่และไม่ได้รับการพิจารณาภายในเวลาที่กำหนด" และส่ง Email ปฏิเสธอัตโนมัติ (ASM-05)
      นับจากวันที่ส่ง ไม่ใช่วันที่เริ่มยืม (Q-APV-15) และไม่ใช้กับคำขอค้างคืน (Q-APV-14)
      ถ้าระบบไม่ได้ทำงานตอนเที่ยงคืน เมื่อเริ่มทำงานใหม่ต้องปฏิเสธคำขอที่เลยเที่ยงคืนของวันที่ส่งแล้วทันที
      ด้วยเหตุผล ผู้ดำเนินการ และ Email เดียวกัน (Q-APV-21)
  (ช) เจ้าหน้าที่ 2 คนกดพร้อมกัน: บันทึกเฉพาะผลของคนที่ดำเนินการสำเร็จก่อน
  (ซ) กรณีดำเนินการไม่ได้ ระบบไม่เปลี่ยนสถานะคำขอ และแสดงข้อความ (ASM-07):
      | กรณี | ข้อความ |
      |---|---|
      | อุปกรณ์ไม่ "ว่าง" (`ITEM_NOT_AVAILABLE`) | "อุปกรณ์ชิ้นนี้ไม่ได้อยู่ในสถานะว่างแล้ว อนุมัติไม่ได้" |
      | คำขอถูกยกเลิกแล้ว | "คำขอนี้ถูกผู้ขอยกเลิกแล้ว" |
      | คำขอพิจารณาไปแล้ว | "คำขอนี้ได้รับการพิจารณาแล้ว" |
      | กดพร้อมกัน (คนที่ช้ากว่า) | "คำขอนี้เพิ่งถูกพิจารณาโดยเจ้าหน้าที่คนอื่น กรุณารีเฟรชหน้า" |
      | ไม่ใช่คำขอแรก | "ต้องพิจารณาคำขอที่ส่งก่อนหน้าของอุปกรณ์ชิ้นนี้ก่อน" |
      | เลย 16:00 น. (Q-APV-11) | "เลย 16:00 น. ของวันที่ยืมแล้ว อนุมัติไม่ได้" |
      | ไม่ระบุเหตุผลการปฏิเสธ | "กรุณาระบุเหตุผลในการปฏิเสธ" |
      | เหตุผลการปฏิเสธยาวเกิน 500 ตัวอักษร (`VALIDATION_FAILED`) | "เหตุผลต้องไม่เกิน 500 ตัวอักษร" (Q-APV-28) |
      | บทบาทไม่ใช่เจ้าหน้าที่ (`FORBIDDEN_ROLE`) | "บทบาทของคุณไม่มีสิทธิ์ทำรายการนี้" |

      | ฐานข้อมูลหรือระบบภายนอกไม่ตอบ (`UPSTREAM_UNAVAILABLE`) | "ระบบขัดข้องชั่วคราว กรุณาลองใหม่อีกครั้ง" (Q-APV-24 ข้อความเดียวกับ 002) |
      | ไม่ระบุชื่ออาจารย์ตอนอนุมัติคำขอค้างคืน (`VALIDATION_FAILED` ช่อง advisorName) | "กรุณาระบุชื่ออาจารย์ที่เซ็นอนุมัติ" (Q-APV-44) |
      | ชื่ออาจารย์ยาวเกิน 100 ตัวอักษร (`VALIDATION_FAILED` ช่อง advisorName) | "ชื่ออาจารย์ต้องไม่เกิน 100 ตัวอักษร" (Q-APV-44) |
      | ไม่มีคำขอรหัสนี้ (`REQUEST_NOT_FOUND`) | "ไม่พบคำขอนี้" (Q-APV-25, แก้ใน v3: คำขอค้างคืนพิจารณาได้ตาม FR-APV-03 แล้ว) |
      ภาควิชาอื่นตรวจก่อนสถานะคำขอ เช่น คำขอที่ยกเลิกแล้วของภาควิชาอื่นได้ `FORBIDDEN_DEPARTMENT` (Q-APV-33)
      ลำดับการตรวจตอนอนุมัติ: ภาควิชา -> สถานะคำขอ -> คำขอแรก -> สถานะอุปกรณ์ -> 16:00 น. (Q-APV-35, Q-APV-36)

      รหัส error ทุกกรณีลงทะเบียนใน CON-TECH-03 แล้ว 2569-11-12 (Q-APV-19 ชื่อรหัสดู plan.md ข้อ 4)
  (ฌ) ประวัติ (RQ-25): ทุกการอนุมัติ ปฏิเสธ และปฏิเสธอัตโนมัติ บันทึกรหัสคำขอ, ผล, เหตุผล (ถ้ามี),
      ผู้ดำเนินการ (รหัสและชื่อเจ้าหน้าที่ หรือ System) และวันเวลา (ASM-09)

  (ค) Email ปฏิเสธอัตโนมัติ (FR-APV-01 ฉ): หัวข้อ "แจ้งปฏิเสธคำขอยืมอุปกรณ์อัตโนมัติ", เลขที่คำขอ, ชื่อผู้ขอ,

      กดส่งซ้ำ Email ที่ส่งสำเร็จแล้ว ตอบสถานะ `sent` เดิม และไม่ส่งใหม่ (Q-APV-37)

## Acceptance Criteria
AC-APV-01 ถึง 15 ทีมอนุมัติ ID แล้ว 2569-11-11 (Q-APV-10, Q-APV-12) / AC-APV-16 ทีมอนุมัติ ID แล้ว 2569-11-12 (Q-APV-13)

  When เจ้าหน้าที่อนุมัติคำขอนั้น;
  Then สถานะของคำขอเป็น `approved` และสถานะของอุปกรณ์รายชิ้นยังเป็น "ว่าง"
- AC-APV-02 (FR-APV-01): Given เจ้าหน้าที่ผ่านการยืนยันตัวตนแล้ว และมีคำขอยืมแบบปกติสถานะ `requested`;
  When เจ้าหน้าที่ปฏิเสธคำขอนั้นพร้อมระบุเหตุผล;
  Then สถานะของคำขอเป็น `rejected` และสถานะของอุปกรณ์รายชิ้นไม่เปลี่ยน
- AC-APV-03 (FR-APV-01 จ, DOM-REQ-01): Given อุปกรณ์รายชิ้นเดียวกันมีคำขอ A (ส่งก่อน) และ B สถานะ `requested`;
  When เจ้าหน้าที่อนุมัติคำขอ A;
  Then คำขอ A เป็น `approved` คำขอ B เป็น `rejected` ด้วยเหตุผล "อุปกรณ์ชิ้นนี้ได้รับการอนุมัติให้คำขออื่นแล้ว" ผู้ดำเนินการคือเจ้าหน้าที่คนนั้น
- AC-APV-04 (FR-APV-02, IF-NOT-01): Given เจ้าหน้าที่เพิ่งอนุมัติหรือปฏิเสธคำขอ;
  When ระบบบันทึกผลสำเร็จ;
  Then ระบบส่ง Email ถึงผู้ขอภายใน 60 วินาที หัวข้อและข้อมูลครบตาม FR-APV-02 (ก) หรือ (ข)
- AC-APV-05 (NFR-SEC-01, IF-IDP-01, CON-TECH-03): Given ผู้ใช้ที่ยังไม่ยืนยันตัวตน หรือมีบทบาทนักศึกษา;
  When เรียกการอนุมัติหรือปฏิเสธ;
  Then ระบบไม่ดำเนินการ ตอบ `UNAUTHENTICATED` หรือ `FORBIDDEN_ROLE` ตามกรณี และสถานะของคำขอคงเดิม
- AC-APV-06 (FR-APV-01 ง): Given คำขอสถานะ `requested`; When เจ้าหน้าที่กดปฏิเสธโดยไม่ระบุเหตุผล;
  Then ระบบไม่ปฏิเสธ แสดง "กรุณาระบุเหตุผลในการปฏิเสธ" และสถานะคงเดิม
- AC-APV-07 (FR-APV-01 ข, DOM-REQ-01): Given อุปกรณ์รายชิ้นเดียวกันมีคำขอ A (ส่งก่อน) และ B สถานะ `requested`;
  When เจ้าหน้าที่พยายามอนุมัติคำขอ B;
  Then ระบบไม่อนุมัติ แสดง "ต้องพิจารณาคำขอที่ส่งก่อนหน้าของอุปกรณ์ชิ้นนี้ก่อน" และทั้งสองคำขอคงเดิม

  Then ระบบไม่อนุมัติ ตอบ `ITEM_NOT_AVAILABLE` แสดง "อุปกรณ์ชิ้นนี้ไม่ได้อยู่ในสถานะว่างแล้ว อนุมัติไม่ได้" และสถานะคงเดิม

  When เจ้าหน้าที่เปิดหน้ารายการ;
  Then เห็นเฉพาะคำขอ `requested` ของภาควิชาตนเอง เรียงตามเวลาที่ส่งจากเก่าไปใหม่ พร้อมชื่อผู้ขอ อุปกรณ์ วัตถุประสงค์ ช่วงเวลาที่ต้องการยืม
